# Casy UI 与现有模块优化方向检查报告

基于 `docs/casy-design-philosophy.md` (v2.4 设计基准)，对当前 Casy 的 UI 和源码模块进行了对比检查。虽然系统已经具备了许多核心能力，但在 UI 架构、透视分类和视觉克制方面，仍有部分模块未完全对齐设计哲学。

以下是需要优化的核心方向记录：

## 1. 导航与信息层级架构 (Navigation Architecture)
**设计哲学基准**：
- 采用三层信息过滤：第一层为全局聚合（今日面板）；第二层为左侧栏核心模块（仅保留 6 个高频操作）；第三层为模块内 Tab。
- 案件是项目的特化形态，不应将“项目”独立为顶级模块。
- 客户视角应当嵌套在案件工作台中。

**现状问题** (`src/App.vue`)：
- 左侧侧边栏采用了 4 个分组（工作台、事项、执行、资料），平铺了多达 9 个模块（今日、案件、项目、任务、日历、数据看板、收件箱、知识库、文书、设置）。
- “项目 (Projects)” 和 “文书 (Docs)” 被独立为顶级菜单，违背了模块收拢原则。

**优化方向**：
- **精简侧边栏**：将左侧栏收拢为 6 个核心入口：**案件工作台**（内含“客户”透视）、**任务工作台**（GTD）、**日历**、**知识库**、**收件箱**、**设置**。
- 将零散的功能归位：例如文书 (Docs) 应作为案件的关联资源或通过 Copilot/Skill 唤起；项目 (Projects) 应与案件 (Cases) 合并。

## 2. 任务工作台 (GTD 透视)
**设计哲学基准**：
- 原则四指出，任务应具有明确的推导透视：📥 收件箱、✅ 下一步行动、⏳ 等待、📅 今日、🔄 回顾、💤 某天。

**现状问题** (`src/modules/tasks/views/TasksView.vue`)：
- 当前实现的 `perspectives` 包含了 `inbox`, `today`, `upcoming (计划中)`, `next (随时)`, `waiting`, `review`, `someday`。
- 多出了“计划中 (upcoming)”，并且“随时 (next)”的语意与“下一步行动 (Next Action，即 `blocked=0` 的行动)”未完全对齐，未能完美体现“案件即流程，完成一步解锁下一步”的理念。

**优化方向**：
- **重构透视 Tab**：严格按照设计稿收敛为：收件箱、下一步行动、等待、今日、回顾、某天。
- 强化“下一步行动”逻辑：过滤出独立的任务以及案件下 `blocked=0` 的任务，不允许出现宽泛的“随时”或“计划中”。

## 3. 案件详情页 (Project Book 结构)
**设计哲学基准**：
- 原则一：案件即顺序项目。详情页应该是一个**项目书结构**，包含顶部概要、项目总览、三轨状态、关联资源、动态轨迹等模块，纵向排列。
- 必须有左下角浮动的“下一步行动”卡片（只能看到 `blocked=0` 的任务）。

**现状问题** (`src/modules/cases/views/CaseDetailView.vue`)：
- 详情页采用了水平 Tab 切换 (`detail-tabs`: overview, tracks, files, timeline)，用户必须点击才能查看不同信息，缺乏一目了然的项目全景。
- “下一步行动”被实现为顶部的 Hero Card，而非悬浮在左下角的引导性卡片。

**优化方向**：
- **废弃 Tab 布局**：将信息改为单页纵向流布局（Header -> 总览 -> 三轨状态 -> 资源 -> 轨迹）。
- **交互改造**：实现左下角悬浮的“下一步行动”模块，完成当前步自动解锁下一步，强化“案件推进”的可执行感。

## 4. 极简捕获系统 (Capture System)
**设计哲学基准**：
- 原则三：先捕获，后整理。
- 提供四个全局快捷键：Cmd+T(任务)、Cmd+E(日程)、Cmd+N(笔记)、Cmd+I(速记)。输入框应极度克制（不要求写标题），默认全部进入收件箱待厘清。

**现状问题** (`src/shared/components/UnifiedCaptureDialog.vue`)：
- 目前实现了一个大一统的 `UnifiedCaptureDialog` 弹窗，其中是一个万能文本框。虽符合“先进入收件箱”，但缺少针对不同意图（任务 vs 日程 vs 笔记）的独立极简输入形态。

**优化方向**：
- 根据用户触发的快捷键（Cmd+T/E/N/I），展示形态不同的极简输入面板（例如任务自动填入时间戳标题，日程带日期选择）。全部统一路由至收件箱进行后续“厘清 (Clarify)”。

## 5. 视觉规范克制 (Visual & UI Tokens)
**设计哲学基准**：
- 原则五：克制即优雅。
- 视觉铁律 2：无 Emoji，无渐变，无装饰性图标。一律使用线性图标。

**现状问题**：
- 通过源码检索发现，大量模块依然散落着 Emoji，例如：
  - `CaseFilesView.vue` (📁, 📥, 📋)
  - `GeneralSettings.vue` (⚙️, 📅)
  - `TasksView.vue` (📋)
  - `WritingView.vue` 及文档组件 (📚)

**优化方向**：
- **全局清理 Emoji**：将所有的 Emoji 替换为 Element Plus 的线性 Icon (如 `<el-icon><Folder /></el-icon>`)。
- 颜色仅用于状态编码（语义红/琥珀/绿/紫），确保界面“信息密度高但视觉安静”。

## 6. 离线提醒与智伴闭环
**设计哲学基准**：
- 离线提醒的 M1 推荐方案是通过日历/日程同步 (CalDAV + ICS via Email)，而非依赖本地进程或飞书自动 PUSH。

**现状问题**：
- `start_reminder_engine` 已在 `lib.rs` 启动，但离线推送的 CalDAV 基础设施和 ICS 固化作业（`reminder_jobs.executor=calendar`）仍需关注是否已经真正落地闭环。日历视图(CalendarView)虽实现了选中时间的分配网格，但与邮件日历的基础设施关联还需核实。

**优化方向**：
- 审查 `src-tauri/src/commands/reminder.rs` 与同步引擎，确保日历同步（CalDAV / ICS）流程顺畅，实现真正的离线准时送达承诺。
