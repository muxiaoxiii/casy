# 案件流程与事实白板 Work Plan（2026-09-08）

## 目标与边界

在既有角色／事件期限引擎上，打通案件、重复收文、转文、传票、庭审与相关程序的管理。纠正路由和异步加载造成的案件串线。事实白板增加可预览的列表、截图、卷宗与知识库引用、丰富的画布编辑和可靠保存。保留原有案件字段与事实历史，不改生产数据，不拆除离线模型。

已完成的基础：程序事件、期限依据与角色判断、关联案件汇总、事实修订审计、完整包清理、可选钥匙串备份。本轮不把这些基础视为流程打磨已经完成。

## 实施顺序

1. **接线审计**：逐一核对案件列表、详情、日历、白板和关联程序跳转；检查路由参数、选中案件、异步请求过期结果、弹窗生命周期。不得在目标案件不存在时静默显示第一件案件。
2. **流程研究与设计**：按提交、收文、转文、送达、指定期限、传票、开庭、延期／取消和后续监测梳理事件。区分材料形成时间与法定起算时间；重复发生的事项使用独立实例及关联，不增加 trial4 等编号字段。法定计算须有来源和适用条件，无法判断时显示待核实。
3. **重复事项实施**：复用已有 hearings 与 procedure_events；核对案件归属、编辑／撤回和来源关联。让用户能够查看并维护多次收文、传票和庭审，明确相互关系与统筹入口。
4. **白板研究与实施**：考察 Excalidraw 的元素／场景／附件存储及 Obsidian 的链接方式；结合现有卷宗、知识库标识和离线约束选择适合本仓库的实现。完善列表预览、图片导入、引用选择与打开、编辑操作、保存与恢复；防止跨案件写入及悬空引用。
5. **验证与交付**：针对路由切换、重复事项、来源引用、保存恢复和迁移做行为测试；运行类型检查、前后端测试与生产构建。最终更新 walkthrough，记录实际完成内容、局限、检查结果与人工复核步骤。

## 验收标准

- 从列表／关联案件／日历打开指定案件，始终保持正确 caseId；快速切换不会显示或保存前一案件数据。
- 同一案件能登记和区分多轮收文、传票及开庭；修改其中一项不覆盖其他实例。收文／转文不能自动冒充有效送达。
- 相关程序能看到各自角色、事项状态和期限来源；延期或撤回事宜保留依据。
- 白板在案件入口可直接预览；可添加截图和本地文件／知识库引用，刷新后仍可查看并定位来源。
- 画布具备可用的编辑、移动、缩放、撤销／恢复能力；已有事实及历史可继续访问。
- 工作计划、研究结论、实施记录和可复核的测试结果留在仓库；真实案件资料与凭据不进入仓库。

## 研究与设计决策（实施中补记）

- 民诉法第 139 条要求开庭三日前通知当事人；这是法院通知义务，不应直接生成律师的法定“交稿期限”。第 149 条列举延期开庭情形，申请与获准必须区分。对应实现：传票为独立收文事件，关联庭审；变更排期保留原日期与决定依据，内部准备时间单独登记。
- 同一轮提交可以有多份转送／收文；每次送达可产生不同主体的期间。采用父事件引用区分轮次，不按文书类别建立唯一字段。来源文件和关联庭审须验证案件归属。
- 检查发现旧版新建庭审会回填 cases.trial_date，后续改期却不同步，造成旧日期残留。本轮停止向旧字段回写，新排期以 hearings 为准；旧导入字段仍保留供核对。
- Excalidraw 官方 README 确认 React 组件可独立嵌入；采用 MIT 许可的 @excalidraw/excalidraw 0.18.1，通过 Vue 容器挂载。Obsidian 插件的可借鉴点是画布文件、嵌入预览和文档链接；不引入 Obsidian 运行时或插件脚本。
- 自托管 Excalidraw 字体，禁用在线 AI 与网页嵌入。场景和图片保存于现有加密数据库，预览为 PNG；保留最近五版。画布中的事实卡片为有来源标识的快照，原始事实修订记录继续独立保留，避免自由绘图覆盖原始摘录。

## 收尾检查补记

- 检查“胜诉／败诉”旧触发器：结果不代表救济期结束，改为仅明确结案／撤诉等状态结束程序；历史导入状态保留并提示核对。统一案件视图的下一次开庭改读有效庭审实例及共享关联。
- v37 迁移回归发现状态更新与全文索引触发器的执行顺序冲突；限制索引更新到真正变更的检索字段，增加新增／改名／删除及索引完整性回归。
- 完整包清理增加依赖许可交付策略：宽松许可且具有独立声明的包才移出重复源码归档；未知／Copyleft／无独立声明者继续随包，原生组件源码与全部模型保留。验证脚本检查声明、必需归档和哈希。
