# Casy AI 调用额度验证

## 修复范围

此前每日计数使用进程内 AtomicU64，重启后清零；聊天先检查、成功后计数，并发请求可以共同通过检查。结构化 JSON、分类、摘要和连接测试等路径没有统一计数，向量请求的计数又分散在调用方。

现在所有 AI 文本后端及向量客户端在 HTTP 发出前通过同一发送函数申请额度。SQLite 即时事务读取已保存的全局每日上限、检查当日计数并递增，提交成功后才发请求。计数保存于设置表的 `ai_usage_v1`，普通设置保存不能覆盖 `ai_` 项；无需新增迁移表。AI 多套配置继续共享用户已设置的每日总上限。

- 重启、切换配置和改变上限不重置已用次数。日期按本机当地日期划分，跨日归零；0 表示不限次数但仍记录用量。
- 统计单位为发出前预扣的请求次数，不是 token、金额或服务商账单。HTTP 错误、空响应和超时保留计数；进程在预扣后被终止也保留该次额度，避免无法确认是否已收费时自动返还。
- 请求参数构造失败和超过上限均在发出前返回错误；读取计数失败时阻止请求，不静默重新从 0 计数。
- 聊天和写作入口不再二次计数。向量索引及搜索的旧预扣已移除，由实际请求统一计数。
- 结构化 JSON 请求使用与其他后端一致的非空响应检查，缺失内容不再被替换成成功的空对象；禁止自动重定向，与已有聊天客户端行为一致。
- AI 设置页每日上限旁新增调用情况入口，显示后端保存的上限、当日计数和剩余额度；加载失败显示不可用。计数不会被表单中尚未保存的上限误导。

所有原生运行显式使用隔离测试目录。界面验证仅连接回环 HTTP 服务并使用合成提示词与合成密钥，不访问飞书或外部 AI，不发送真实案件材料，不启动后台同步。

## 剩余交付门槛

本批验证调用配置、请求路径和次数控制，不代表真实模型的法律回答、结构化抽取或语义检索准确率已经验收。文本分类中畸形模型 JSON 的降级行为仍需独立复核；长卷宗 OCR、超大数据集、系统日历恢复与其他整体 UI 门槛继续保留。没有更新已安装发行版或正式数据库。
