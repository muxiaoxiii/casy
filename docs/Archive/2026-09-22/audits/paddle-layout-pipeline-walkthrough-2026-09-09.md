# Paddle 文档版面与进度数据链路实施记录

实施日期：2026-09-09

## 结果

Casy 文档引擎统一使用本地 Paddle ONNX 管线：PP-OCRv6 medium 负责文字检测与识别，PP-DocLayout Plus-L 负责复杂版面语义，规则表格恢复负责有线表格，原页裁剪负责保留图表、公式、印章和无法可靠恢复的表格。运行时不包含第二套 OCR 引擎。

## 版面保留

每页 Page IR 除文字、坐标和 Markdown 外，还保存：

- Paddle 原始版面类型、置信度和边界框；
- 稳定阅读顺序，以及版面块到 OCR 行的索引映射；
- 表格行列、跨行跨列、单元格边界与文字归属；
- 图表、公式、印章等视觉区域及语义提取状态；
- 无法可靠恢复的表格数量，不把猜测结构伪装成确定结果。

标题、列表、页眉页脚和脚注会按 Paddle 语义进入 Markdown。结构化版面同时写入独立页文件、完整 Page IR、数据库 `document_pages.layout_json`，并由页面查看命令返回；人工校订产生新版本时继续保留。

## 进度与耗时

引擎原子更新 `progress.json`，阶段包括准备、渲染、文字识别、复杂版面分析、结果整理和完成。快照包含累计耗时、预计剩余耗时，以及最近一页的渲染、OCR、版面和总耗时。

Tauri 桥接以该快照为唯一进度来源，同步更新持久化任务并发出实时事件。文件转换弹窗和全局处理中心因此显示相同的页数、阶段、elapsed、ETA 和最近一页耗时；最终结果中的 `elapsedMs` 与完成事件保持同一口径。

## 运行时

打包运行时包含约 132 MB 的 PP-OCRv6 medium 和约 124 MB 的 PP-DocLayout Plus-L。版面模型现在是文档引擎可用性的必需项；探测缺失时明确返回 `CASY_LAYOUT_MODEL`，不再静默降级为仅有文字顺序的结果。

## 验证

- 文档引擎模型功能测试覆盖多栏阅读序、版面块映射、表格、视觉对象、可搜索 PDF 和双流文本校验。
- Rust 处理中心测试覆盖迁移、持久化 elapsed/ETA/最近页耗时及跨案件状态聚合。
- Vue 组件测试覆盖实时转换耗时明细与处理中心持久化耗时展示。
- 类型检查覆盖新增 Page IR、页面查看和处理中心字段。
