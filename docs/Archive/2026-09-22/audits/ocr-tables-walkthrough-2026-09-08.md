# OCR 表格修复 Walkthrough（2026-09-08）

对应 [Work plan](ocr-tables-work-plan-2026-09-08.md)。本轮改动未提交，未替换 `/Applications/Casy.app`，未操作生产数据库；真实报告只在本地处理。

## 根因

原引擎仅做 OCR 与版面阅读顺序，之后直接 `markdown = plain_text`。即使 layout 模型识别出 table，也没有单元格、行列或合并结构输出。密集表格中的样品列、检测项目行及跨行依据因此失去关系。此前 OCR 回归主要覆盖文字、页码、阅读顺序和来源绑定，没有覆盖表格结构质量，不能据此前测试认定复杂表格可用。

本次检查了已安装 OAR 0.9.2 的 `table_analyzer`、表格结构识别／单元格预测器及 [官方项目](https://github.com/greatv/oar-ocr)。现有安装包有文字与版面模型，但没有配置 SLANet 等结构模型。当前实现先用实际可见网格恢复有线表格，不额外增加模型、不调用外部 AI。

## 实现

- `tools/casy-doc-engine/src/table.rs` 从 layout 表格区域内的深色连续边框恢复行列，校正小角度扫描倾斜；区分长直线与对齐的文字笔画。
- 根据真实边界的存在／缺失恢复合并单元格，要求矩形拓扑，限制行列和总单元格数。边界依据不足时放弃结构推断，并显示“表格结构待核对”，不把普通多栏正文伪造成表格。
- 匹配 OCR 文字与单元格，处理倾斜长文本包围框的归属；跨越两个单元格的文本框分别裁切、重新 OCR，不按字符比例猜分。任何裁片未读出文字时保留完整原行供核对。
- 输出 HTML table 嵌于 Markdown，使用 `rowspan` / `colspan` 保留合并；多行内容保留换行，比较符号、尖括号和 `&` 正确转义。斜线表头中的两组文字保留在同一格，不伪造轴归属。
- 大型交叠印记等不能可靠归位的文字列于核对区，不混入数值单元格。并未按特定水印名称硬编码删除任何内容。
- 每页保留原 OCR 行、表格结构及单元格到区域索引的本地 JSON。结构算法版本记入模型版本信息。原始 PDF 和模型不变。
- 表格中的文字使用稳定区域标记；source map 只在唯一、内容完全匹配的标记上恢复坐标，不为重排页面编造坐标。
- 校订单个 OCR 区域只替换对应内容，保留表格结构。标记不匹配时不假装能准确更新结构。
- 文件“对照阅读”默认显示经过消毒的排版预览；同时保留逐行识别和 Markdown 源码。预览白名单保留跨行列属性，继续移除执行属性及内部区域标记。
- 已完成任务新增“重新识别（保留旧版）”。新任务使用新 ID，旧结果不删除，不会被缓存挡住；旧版手工校订不自动混入新识别结果，界面明确说明。禁止重复启动或对非最新任务重新处理。

## 适用边界

当前自动恢复针对有清晰边框、近似正交且只有小角度倾斜的表格。无边框、严重透视／弯曲、断线或复杂非矩形结构尚不能保证恢复；检测到但无法恢复时明确提示核对。没有声称所有表格已解决。

数值质量验证针对本次报告。水印、手写签名、印章及个别非数值文字仍可能有 OCR 错误；例如“见下页”未保证准确，不用结构校验掩盖文字识别误差。没有对原件进行语义补写或自动校正实验结果。

旧识别不会自动被升级结果覆盖：在文件内选择“重新识别（保留旧版）”，或重新执行独立格式转换，即可使用当前引擎。
