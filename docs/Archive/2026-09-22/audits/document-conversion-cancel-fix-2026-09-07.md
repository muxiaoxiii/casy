# 独立 PDF 转换立即取消修复

## 原因

独立转换入口生成随机任务 ID，但不登记 `document_processing_jobs`，随后调用了供案卷后台任务使用的引擎执行函数。执行函数在第一次 interval tick（立即触发）查询数据库任务状态，并通过 `unwrap_or(false)` 将找不到记录和 SQL 错误均解释成“不在运行”。函数立即返回 `CANCELLED`，`kill_on_drop` 又终止刚启动的引擎，所以用户看到的是点击即取消。

这不是文件选择取消、用户手动取消或取消通道关闭。旧桥接二进制在内置引擎已准备好的情况下处理合成扫描 PDF，也立即返回相同错误。

日志另有独立缺陷：`app_log::init()` 中的非阻塞日志 WorkerGuard 是局部变量，初始化返回后即释放，后台文件写入线程不能继续工作。这解释了为何有初始化记录，却没有后续诊断。

## 修改

- 新增独立引擎入口，只跳过数据库任务状态和进度回写，保留进程退出检查、输出限制、15 分钟无页码进展超时、产物和源文件校验。
- 案卷后台任务继续检查数据库状态；只有明确 `cancelled` 才返回取消。缺失/停止的任务和 SQL 错误分别报告状态变化、状态读取失败。
- 日志初始化返回 WorkerGuard，由主应用持有到运行结束；转换记录关联任务 ID、引擎启动/PID、页码进度、退出状态及最终成功/失败。正常日志不记录正文。
- 开发版自动查找仓库 `src-tauri/runtime`，避免资源已经准备好却仍要求设置 `CASY_DOC_ENGINE`。release 继续使用应用内置运行时。
