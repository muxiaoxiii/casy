# 全局处理中心工作计划

需求：后台处理必须有统一入口，跨案件、跨页面完整可见；不能用弹窗的局部状态代替真实任务。

1. 在顶部增加常驻处理中心，显示正在处理和排队数量。所有案件的 OCR / PDF、后续文档索引、知识索引及单独转换任务统一查询，历史分页，不截断为最近 100 条。
2. 增加持久化活动记录；单独转换的整批等待项先登记，进度、输出位置、错误和退出中断均可追踪。弹窗可以收起到后台。
3. 盘点目录同步、向量缓存、飞书自动推送、日历提醒、邮件监听及定时重算/报表等服务。周期轮询显示最近状态和等待计划，实际任务保留历史；不会把等待下一次触发算作正在处理。
4. 保留原件、旧 OCR 结果及既有导入策略。明确“开始识别并生成可搜索 PDF”，说明添加文件不等于已经进入 OCR 队列。
5. 检查跨案件查询、分页、阶段衔接、失败恢复、跳转参数、关闭弹窗及卸载后的轮询清理。只使用隔离数据库，不修改用户正式数据库。
6. 完成类型检查、针对性回归和完整 ARM Mac 安装包验证，记录 walkthrough；其他平台的现存依赖限制如实保留。

实施与交付已完成，测试和实际 DMG 验证通过；Mac 锁屏导致新增界面的实机点击验收待补。具体证据见 [walkthrough](processing-center-walkthrough-2026-09-08.md)。
