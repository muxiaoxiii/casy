# 统一编辑器与导出升级 Work Plan

状态：实施中。日期：2026-09-08。正式数据与当前安装不修改；隔离原生实例验收后记录 walkthrough。案情梳理重新设计继续保留，白板旧方案暂停交付。

## 审计结论

知识库和文书工坊均使用 Tiptap，但各自重复维护编辑器、扩展、工具栏和样式。知识库经 Markdown/HTML 桥保存，文书保存 HTML。用户问题均有代码依据：新文档预填提示文本、任务列表缺少 Markdown → Tiptap 结构转换、工具栏隐藏横向滚动、固定 3×3 表格、普通图片节点无编辑界面、分散的导出入口。不能靠重新换一个第三方编辑器解决。

## 实施

1. 提取同一编辑器主体，两处通过 Markdown / HTML 存储适配接入，保留文书案件字段建议、证据引用、知识捕获和已有保存冲突／恢复保护。既有页面不批量改写正文，不自动删除旧提示文本，避免误删用户内容。
2. 统一简洁工具栏：常用操作常驻，宽度不足的操作收入“更多”；明确区分列表与表格。表格在按钮旁打开行列选择器、数字输入与表头选项，支持键盘；已有表格行列维护保持可见。
3. 补齐内容往返：待办状态、嵌套列表、合并表格、图片大小、链接／引用不能在切换页面或编辑模式时消失。图片提供选中边框、大小调整与图前／图后继续输入；粘贴及导入图片保存为可携带内容。
4. 新建文档正文为空，提示只作为编辑器 placeholder 展示；移除产品界面中的 Notion 名称。两处快捷键、浮动工具、正文样式和表格／图片操作一致。
5. 待办默认是文内清单，通过显式“关联任务”创建或选择任务；保留稳定标识。同步勾选状态并显示错误／失效关联，禁止仅按待办文字匹配任务，禁止清空正文时删除真实任务。任务中心变更应在重新打开／刷新时反映到文内。
6. 统一导出入口与布局规范，支持 MD / PDF / DOCX；原生选位置，取消不报成功，原子写入；直接读取当前文档，不通过临时切换编辑模式获取导出数据。PDF 需真实分页与可选择文字，不能以长截图冒充。复用已有中文字体与原生能力，不引入整套浏览器运行时。

## 验证

- 用真实 Tiptap 编辑器测试 Markdown → 编辑 → 保存 → 重开，覆盖未完成／已完成／嵌套待办、图片宽度、表格及引用。
- 两个模块使用同一编辑组件；窄编辑区仍能通过更多菜单执行所有工具，表格行列可选，空白文档导出不含提示。
- 待办关联与完成状态同步测试包含重复点击、另一处更新、任务被移除和错误保留。
- 三格式导出用同一含中文、标题、列表、待办、图片与跨页表格样例，检查文本、图像尺寸、表格结构、分页及输出失败不覆盖旧文件。
- 独立原生应用用 CUA 实际操作知识库与文书工坊，不以 mock 或只通过构建代替验收。
- 实施完成后记录实际测试证据与剩余限制，不将未实施方案写作既有能力。
