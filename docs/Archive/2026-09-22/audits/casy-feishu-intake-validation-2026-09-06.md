## 录入与交互变更

- 新建表单覆盖基本信息、当事各方、审理与专利、日期与期限、费用与备注、办案节点和关联案件。
- 第三人支持多条记录，分别保存名称、地位、代理人、代理律所和联系方式。新建、案件概览和属性编辑均可访问。
- 支持从带字段名的资料文本提取信息，并提供现有当事人、法院等输入建议。程序切换会调整默认地位，保留用户主动选择的地位。
- 新建窗口可同时填写庭审、办案日志、任务和官方联系人。主案与子记录及关联关系在同一数据库事务中提交。
- 保存期间阻止重复提交；后端失败时保留表单并显示错误；保存成功后关闭。取消有未保存变更时提示。
- 新建和后续属性编辑共用字段目录，避免出现“能创建却无法再次编辑”的字段。
- 关联案件支持按名称、案号、当事人或专利号搜索；从当前案件新建关联案时带入共同当事人及专利信息。
- 修复详情页关联案跳转路由名错误，避免已保存后因跳转失败显示为创建失败。
- 详情庭审编辑保留时分秒，状态值与数据库约束一致。
- 修复案件联系人联合查询中 id 等列名歧义，确保新建时录入的官方联系人可正常回读和显示。

## 导入实现

入口为“批量导入 → 整库 / 关联导入”。支持读取本地 JSON 快照，或只读获取整库后预览、保存快照，再写入本地。可选择全部案件，或指定案件及其显式关联案件。

按记录 ID 重建关系，不依赖显示名称或“案号 LIMIT 1”进行跨表匹配。保留原始字段、公式定义与当次结果、记录 ID、选项标签及附件元数据。“全量属性与字段”下可检查导入原始记录并导出本地附件。附件同时进入案件卷宗。

日期按字段类型转换为北京时间；日期字段保留日期，包含时分的字段保留完整时间。普通大数不会误当成时间戳，富文本片段不会无故插入顿号。

单表导入中的日志写入也修复了不存在的 operator 列、缺少 event_summary 和非法 event_type；缺失日期会列入错误，不再填入固定日期。

## 使用边界

- 本轮没有替换用户正式案件库，也没有更新已安装的发行版。验证对象为当前工作区代码和隔离测试数据库。
- 快照导入默认保留已导入对象及其本地修改，是一次性导入流程，不是云端增量同步。
- 飞书公式保存定义和当次结果；Casy 的期限引擎及时间线按自身规则运行，并不执行任意飞书公式。历史公式日期与后续动态计算应区分使用。
- 资料提取为本地带字段名文本解析，不会将真实案件资料发送给外部 AI。
- 多行第三人逐条保留；重复案号等冲突字段保留原行供核对，不静默覆盖。快速切换案件时丢弃过期原始记录查询结果。
- 通用新增表可以保留原始数据，但本轮业务投影验证覆盖的是这份快照中的五类工作表。
