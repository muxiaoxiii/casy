# Casy 捕获与完整案件录入验证

## 范围

本批衔接既有案件录入、任务及笔记编辑批次，修复捕获窗口的完整案件录入、附件保留、失败重试与确认后的列表刷新。飞书仅使用已有私有本地快照，没有访问飞书网络接口，没有修改线上表格、正式案件库或已安装发行版。合成数据的界面验收使用真实 Rust 命令、独立加密数据库，不启动同步或外部 AI。

## 行为变化

- 捕获案件进入完整 CaseWizard，支持当事各方、多位第三人、代理人与联系方式、费用、日期、办案节点和关联案件；保留原始资料文本。案件数组和数值字段在后端规范化，避免前端校验通过后反序列化失败。
- 日期与时间可按任意先后顺序录入，支持“明天下午三点”“下周一”及任意分钟。非法日期不滚动到另一日期；明确选择日程时必须确认日期。
- 捕获先保存本地原始内容，显式分析入口才使用配置的 AI。文件立即复制到受管理目录并校验 SHA-256，后续删除原文件不影响已捕获附件。
- 文本与多个附件部分失败后保留全部输入，仅重试未成功部分；附件归档失败可继续重试。无关联案件的附件继续留在收件箱。
- schema 31 增加处理结果回执。任务、期限、提醒、日程、知识、案件、项目及假期设置的业务写入、收件状态、反馈和回执在同一事务中提交。确认响应丢失或并发确认时返回原结果，不重复创建。
- 任务保存收件来源及审阅字段；知识保存原始 Markdown、来源和案件关联，并同步 Wiki 引用。
- 附件归档采用不覆盖写入。同名文件自动另取名称，登记失败只清理本次新副本，既有卷宗不受影响。
- 成功确认后刷新当前案件、任务、日历或知识视图。捕获中的案件表单按需挂载；360×640 捕获窗口与 390×844 第三人输入区检查可见范围，避免确认按钮或输入被底栏挡住。

## 复现

```sh
npm run build
npx vitest run --config vitest.config.ts
cd src-tauri
CASY_TEST_DATA_DIR=/path/to/isolated-profile cargo test --lib --tests
CASY_TEST_DATA_DIR=/path/to/isolated-profile cargo build --example capture_local_bridge --example intake_local_bridge --example knowledge_local_bridge
cd ..
CASY_QA_URL=http://127.0.0.1:1423/ CASY_QA_DIR=/path/to/private-artifacts CASY_PLAYWRIGHT_MODULE=/path/to/playwright/index.mjs node tests/e2e/capture-local.mjs
```

案件回归使用同目录下 `intake-local.mjs`，私有目录需包含既有 `snapshot.json`。任务和笔记回归分别使用 `tasks-local.mjs`、`notebook-editing-local.mjs`。截图和数据库保留在仓库外的私有测试目录。
