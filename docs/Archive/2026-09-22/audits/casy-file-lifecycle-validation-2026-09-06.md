# Casy 卷宗文件生命周期验收

## 本批变更

- 导入先检查全部输入，再暂存复制、校验 SHA-256，最后在单个数据库事务中登记。输入中的重复路径只登记一次；已有登记复用 ID；无效路径或后续登记失败会回滚本批新文件。
- 重命名和同案目录移动使用不会覆盖目标的文件创建方式，遇到重名自动追加序号。批量操作失败回滚，成功后保持文件 ID、页索引、文档任务及知识引用；清理旧副本失败会返回提示。
- 案号变化后沿用已保存的卷宗目录。拒绝上级跳转和越界目录；目录列表覆盖根目录及嵌套子目录。
- “移除登记”保留磁盘文件和引用，可在已移除列表恢复。移除会取消待处理和运行中的文档任务，并从正文检索、知识来源、规则处理和全局文件搜索中排除。
- 恢复前检查原文件。内容变化时清除过期正文索引并要求重新处理；已沉淀的历史知识笔记保留。原文件缺失时明确报错。
- 修复文件 FTS 更新触发器被更新时间触发器重复执行的问题。规则执行与文件存活检查使用同一事务。
- 卷宗界面增加目录选择、新建文件夹、多选移动、分类修改、重命名和恢复登记。文档状态按案件批量读取，避免逐文件轮询。
- 修复智能重命名中文短日期生成 `undefined`，以及界面不显示实际重名后文件名的问题。
- 关联案件保留各案数据归属。移除旧版“永久转移数据”入口，后端拒绝 `mergeData=true`，避免静默部分转移和卷宗路径错位；普通关联及导入建立的共享子表引用保持可用。

## 使用边界

- 本批处理同案文件夹移动。关联不是案件合并，不提供跨案搬移或完整案件合并功能。
- 移除登记不释放磁盘空间，恢复要求原文件仍存在。
- 文件复制和数据库使用失败补偿，不是跨文件系统与数据库的持久事务日志。进程突然终止可能留下未登记副本；原文件在数据库提交前保留，提交后无法清理旧副本时提示用户。
- 托管目录需要支持硬链接。未验证外接磁盘、网络文件系统和 Windows 的全部边界。
- 数据目录迁移后旧绝对路径不会自动修复；不猜测缺失原件的来源。
- 本批不证明超大卷宗吞吐、复杂 OCR 版面、真实模型回答质量或完整 GTD 已达到交付门槛。

## 复现

```sh
npm run build
npm run test:unit
cd src-tauri
cargo test --lib --tests
cargo build --example document_local_bridge --example intake_local_bridge
cd ..
CASY_QA_DIR=/path/to/private-artifacts CASY_QA_URL=http://127.0.0.1:1422/ CASY_PLAYWRIGHT_MODULE=/path/to/playwright/index.mjs node tests/e2e/file-lifecycle-local.mjs
```

先完成前端构建，再执行 Rust 编译，避免 Tauri 嵌入资产时碰到 Vite 清理输出目录。浏览器端需要运行 Vite；其他录入与正文检索脚本分别为 `tests/e2e/intake-local.mjs`、`tests/e2e/text-document-local.mjs`。
