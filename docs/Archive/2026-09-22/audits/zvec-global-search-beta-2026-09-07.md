# Zvec 与全局检索 beta 验收

日期：2026-09-07。用户授权在知识库引入 Zvec，并将知识检索接入全局搜索。测试仅使用隔离的合成资料库，没有访问飞书或操作正式资料库。

## 实现

- 使用 Zvec 0.7.0 官方 C SDK、`zvec-rust`/`zvec-rust-sys` 0.7.0，原生进程内 HNSW，替换知识分段向量的全量线性扫描。SDK 下载固定 SHA256，并携带 Apache-2.0 许可及来源记录。
- 索引为 FP16、cosine、M=16、efConstruction=200，查询 ef=256。官方 SDK 的 cosine 不支持原始 INT8 字段，FP16 字段也不能再叠加 INT8 量化，因此本版没有声称使用 INT8 HNSW。
- SQLite 保留原有 INT8 紧凑向量及正文，HNSW 负责找候选，再对候选按 SQLite 向量精排，并与 FTS 通过 RRF 融合。现有本地章节路径和跨页文本切分继续有效。
- 同一笔记的多个分段去重，多轮查询排除已经命中的笔记，防止一篇长文挤占全部候选。返回结果按数据库当前状态验证。
- 全局搜索新增“关键词 / 混合检索”，先显示关键词，再异步补充知识语义结果。保留任务、案件、个人项目关键词结果；语义检索对象是知识笔记和导入的 Markdown 分身，没有为任务和案件实体额外生成向量。
- 点击知识结果直达笔记正文，支持命中列表首批 2000 条以外的笔记。切换查询、关闭搜索和卸载组件均丢弃过期结果。
- 关键词搜索无需模型。混合搜索复用设置中的向量模型；选择内置多语言 E5-base 后，向量生成和 Zvec 检索均在本地完成，不消耗云端大模型 token。

## 持久化与恢复

- Schema v33 增加数据库与索引任务的随机修订标识及触发器。后台在向量任务空闲时同步缓存；常规查询先读取单个修订标识，仅在变化后检查任务并更新相应分段。
- 缓存目录为资料库旁的 `indexes/zvec-v1`。模型切换重建同一目录；归档、删除、正文修改和向量替换触发同步。
- 独占文件锁防止多进程同时写入。更新前删除有效 manifest，更新完成后 flush 并原子持久化；中断、损坏或缺失时从 SQLite 重建。
- 自动完整备份不打包派生的 `indexes` 目录。数据库内的紧凑向量保留，恢复后通过修订标识重新同步，无须再次调用模型。
- Zvec 缓存不包含标题和正文，但包含向量、哈希 ID 和内部任务修订信息。该缓存不受 SQLCipher 加密；Unix 目录权限为 0700。向量仍是派生业务数据，不能将此目录描述为加密存储。
- Zvec 或模型失败时保留关键词结果并展示错误；不会悄悄退回全向量扫描。

## 使用

1. 在 AI 设置启用语义检索并选择内置多语言 E5-base，保存并测试。
2. 在知识库的“知识库检索 / 索引任务”执行“更新全部索引”。既有当前模型的向量可直接重用，由后台建立 Zvec 缓存。
3. 知识库或顶部全局搜索选择“混合检索”。全局模式会保留到下次打开。

## 发行边界

本轮交付 Apple Silicon 完整本地 beta，使用 ad-hoc 签名，没有 Apple 开发者签名或公证。Zvec 官方 macOS SDK 最低要求 macOS 15，但现有打包 PDF 渲染器 `pdftoppm` 的 Mach-O 最低版本为 macOS 26；完整包因此声明 macOS 26.0，不能宣称支持更早系统。Linux/Windows SDK 下载准备已提供，本轮没有验收它们的安装发行。

打包后原生探针发现 ad-hoc 进程没有 Team ID，Hardened Runtime 默认库签名校验阻止加载 Zvec。完整 beta 配置使用 `entitlements.beta.plist` 授予 `com.apple.security.cs.disable-library-validation`，保留其余 Hardened Runtime 保护。将来使用 Developer ID 发行时，应统一签署嵌入库并移除此 beta 权限，重新验收签名公证。

用户已决定后续自行验收真实案卷；OCR 复杂跨页表格重建、LEANN 重算与对任务/案件实体的语义索引不在本次实现范围。
