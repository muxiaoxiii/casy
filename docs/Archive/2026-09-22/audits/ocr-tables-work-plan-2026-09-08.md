# OCR 表格修复 Work Plan（2026-09-08）

## 问题和目标

用户报告表格 OCR 不可用。检查现有引擎发现 `markdown = plain_text`，版面表格类别仅参与阅读顺序，未做单元格结构恢复。此次用用户本地三页检测报告复现，所有原件与识别产物保留在仓库外，不上传外部服务、不修改原件。

## 实施顺序

1. 保留旧引擎结果，对照原 PDF 页面，区分文字识别错误与行列／跨行列结构丢失。
2. 检查现有 Paddle/OAR 表格能力和本地模型约束。优先实现有充分图像依据的有线表格结构恢复，保留合并单元格；不按猜测将任意多栏正文拼成表格。
3. 把结构结果接入 Markdown 输出、页面中间结果和来源映射。格式转义不得改变小数、比较符号等原文字义；不可靠结构明确保留原文与核对提示。
4. 以合成通用表格回归验证列错位、跨行列、空格、跨单元格 OCR 框、转义、扫描倾斜和普通正文回退；真实报告核对样品列、元素行、全部数值与依据覆盖范围。
5. 验证转换及知识库接线，生成修复后的可复核结果和完整安装包，记录 walkthrough 与实际边界。此前案件管理和白板改动保留。

## 验收

- 真实表格恢复明确的行列关系与合并单元格；不得只以关键词出现作为质量通过标准。
- 没有图像／检测依据时不生成虚构单元格；无法可靠恢复必须可见。
- 识别值保留来源坐标；原始 OCR 与结构化输出区分，避免把重排后的整页虚构成单行坐标。
- 原件哈希保持不变，真实案件数据不写入 Git。

## GDS 与安装反馈追加（同日）

用户实测新版 OES 表格正确，但 GDS 第 2 页局部列线漏检。将 GDS 原件纳入回归，核对四列元数据与合并范围；增加灰色细线的通用回归，复跑 OES 数值校验，不能以一个报告通过替代一般质量验收。

同时追踪重复图标的实例／安装来源，清理本任务遗留测试副本。检查钥匙串的所有被动状态读取路径，以及既有加密库缺少本地密钥时的恢复路径：已验证的旧密钥需要安全持久化，避免每次启动重复授权；不得生成新密钥替换旧库。
