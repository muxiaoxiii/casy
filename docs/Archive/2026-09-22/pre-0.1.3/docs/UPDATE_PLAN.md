## 阶段一：长任务与大文件

### 任务结果契约（R-06）

为独立转换以及完整备份/导入等长写操作提供稳定 job ID，查询状态、进度、最终结果及输出清单。利用现有 processing/background jobs 设施前先明确它们各自的持久化和恢复语义。前端断开、超时或切换页面不得擅自宣告任务失败或启动同一写入的重复任务。

实现取消请求及后端确认、幂等重试、应用重启后的恢复或明确中断。区分渲染、OCR、输出提交等阶段的进展/心跳，避免仅凭页数不增长误判耗时收尾。取消不能删除已经属于用户的原文件或已确认产物。

**完成标准：** 超过 3 分钟仍准确显示状态；断开/重连可取得同一结果；取消有确定终态；重启后不会留下假“进行中”；重复提交不会重叠写入；失败/部分成功都有对应产物说明。

### 资源预算与增量处理（R-02）

- OCR 页数据、裁图、来源映射逐页持久化；减少进程间重复传完整页集合和主程序二次完整解析。
- Markdown 与 PDF 导出采用增量/流式写入及复制；源图尽早外置，同时保留来源哈希和校订绑定。
- 对必须整份解析的 Office/文本库明确内存预算与隔离方案；通过测量决定实现，避免仅取消常量便宣称支持无限文件。
- 协调 16 MiB 工作区读取、40 MiB 编辑器导出、128 MiB 校订边界；无法整份编辑时提供分页/分段入口和清晰提示。

**验收样本与记录：**

| 样本/场景 | 必查结果 |
| --- | --- |
| 已生成的 >64 MiB 含真实 PNG Markdown | 完整转换、图片哈希、无内嵌 base64 的用户输出；目前仅生成输入，尚未验收 |
| 少量超高分辨率页及长扫描 PDF（建议 100/500 页分档） | 峰值 RSS、临时磁盘、每页耗时、收尾耗时；页数增长时内存不持续线性累积 |
| 有文字层/无文字层、图表和多语言混排 | 无页遗漏、来源映射一致、派生 PDF 可检索 |
| 取消、终止后重启、磁盘满、只读目标目录、原件中途改变 | 明确终态、源文件不受损、临时资源清理、已提交产物可追踪 |

记录设备内存、系统版本、样本字节/页数、峰值 RSS 和临时磁盘。先测现状，再确定具体预算，不虚构尚未验证的容量保证。必须显式运行新增 `accepts_text_source_and_extracted_markdown_larger_than_64_mib` 用例，不能再次依赖未命中的 `document_` 过滤器。

## 阶段二：导出完整性

**R-03：** 将 Markdown 的源目录、附件解析与输出策略作为明确参数；迁移已引用本地图片并重写相对路径，按内容处理去重/冲突，保留原件。覆盖中文空格路径、跨目录二次导出、已有 `casy-images-…`、缺失附件和不允许读取的路径。确认移动整个输出目录后仍正常显示；不默认抓取远程资源。

**R-04：** 建立前后端一致的输入/输出能力表。当前文本→双层 PDF 在转换前明确拒绝或隐藏；将来若支持，单独实现并验收。定义“两者”输出的暂存/提交/回滚策略，出错时要么没有新发布文件，要么明确报告部分成功及实际路径，不能仅返回笼统失败。

**完成标准：** 所有开放格式组合都有成功用例；不支持组合在写入之前返回说明；中途失败和同名输出可验证；三处 Markdown 出口的附件行为有统一文档。

## 阶段三：业务状态可靠性

**R-05（P1）：** 自定义规则新增/修改/启停与审计统一事务，明确定义删除后的求值失败反馈。故障注入验证审计失败时变更回滚、提交后刷新失败不误报未保存、重复请求不会重复创建。保持程序事件的乐观锁、事务和处理状态指纹契约。

**R-07（P2）：** WebDAV 状态取自配置与实际活动；明确“已配置”和“当前可达”的区别，保留最后成功/失败时间与原因，避免固定 false。无配置、离线、认证失败、同步中及成功五类状态有验收；敏感凭据不进入响应或日志。

**完成标准：** 状态读数可与持久化记录对照；异常情况下界面与实际写入一致。期限规则仍需按独立规则依据核实，代码审阅不替代法律适用审查。

1. 在冻结源码上运行相关全量回归、真实转换样本和包内测试；验证完整离线首次启动。
2. CI 增加独立 engine crate 测试、runtime manifest/许可/架构校验、真实包内 OCR 与向量检索样本；清除开发机资源覆盖变量。
3. 构建后核对应用版本、引擎/模型、目标架构、最低系统版本和资源清单；DMG 挂载验证，保存校验和及构建清单。
4. 将 DMG 失败的诊断和必要替代流程变成可复现步骤；自动化之前保留人工验收记录。
5. 核对签名与公证状态、更新签名及下载链路。当前 updater artifacts 关闭，不能凭配置公钥宣布自动更新可交付。
6. 对齐正式隐私/EULA 与现有网络、密钥、附件和授权行为；保留第三方许可与所需源码。技术文档不能代替正式条款审定。

**发布条件：** 纳入发布范围的 P1 问题已解决并验证，P2 的处置和限制已记录；新安装包内实际代码与版本一致；没有把旧 0.1.1 bundle 重命名当作 0.1.2。若大文件仍未通过验收，应收窄能力声明并明确限制，不能宣传任意大小稳定转换。
