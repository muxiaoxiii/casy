# 案件流程与事实白板 Walkthrough（2026-09-08）

对应计划：[Work plan](case-workflow-whiteboard-work-plan-2026-09-08.md)。本文件记录本轮最终行为与复核方法；工作区改动未提交，未替换已安装的 Casy，未写入生产案件库。

## 案件管理与接线

- 列表选中案件写入 `caseId` 查询参数，返回列表恢复原案件。目标不在当前分页／筛选中时进入该案件详情，不静默回退第一案。详情页消费 `tab` 查询参数，日历庭审打开庭审页，程序事项打开程序页。
- 列表文件、目录、任务、事件以及详情并发加载加入案件身份／请求版本检查，旧响应不能覆盖新案件；共享案件 store 也保护乱序请求。案件读取失败清空旧案并显示错误。
- 详情知识检索先等待正确案件；修复原先 `eventDate/detail` 被错误读作 `date/description` 的时间线接线。
- 列表时间线接入完整案件轨迹，不再仅依靠当前月份日历展示庭审。收文／转文事件纳入时间线，支持返回原记录维护；归卷日期明确不代表实际收文或送达日期。

## 多轮收转文、传票和庭审

- 新增收文、转文、传票／口审通知、延期／改期／取消通知事件类型。每份材料独立登记，可以关联同案前序事件、来源卷宗与某次庭审；同次庭审可关联多份通知。
- 事件 ID 与修订号保证不同轮次不会相互覆盖。来源校验拒绝错误案件的文件或庭审。转文日、有效起算／送达日、明确截止日继续分别保存。
- 庭审状态支持已排期、已开庭、延期待定、已取消。改期／延期／取消要求记录通知或决定依据；数据库保留改动前后日期、地点和状态，统一显示于程序修订记录。
- 延期待定在统筹页保留“跟进新排期”待办，不把旧日期当作下一次开庭；取消排期不再进入待办。对应日历和庭审提醒排除已延期／取消日期。
- 庭审提醒按具体庭审、排期与渠道去重；支持带时分的庭审日期。同一案件第二次庭审不再被第一次提醒吞掉。变更后取消尚未发送的本地旧提醒作业。
- 新建庭审停止回写单一 `trial_date`，避免改期后旧字段继续冒充现行排期。旧导入字段保留供核对，不自动删除。数据库迁移到 schema 37，新增场景、场景版本、庭审状态与提醒去重记录。
- v37 统一视图的“下一次开庭”取有效庭审实例与明确共享关联；已有庭审实例时不再退回旧 trial_date。胜诉／败诉不自动结案，历史导入的矛盾状态显示核对提示。仅明确结案／撤诉等结束程序。状态写入不再误触发全文索引删除，新增／改名／删除与 FTS 完整性回归通过。
- 相关案件依各案身份分别计算期限，同日庭审提示统筹核对。申请延期／中止不自动停止任何其他程序的期限。

## 事实白板

- 默认自由画布采用 Excalidraw 0.18.1，支持手绘、形状、箭头、文字、图片、缩放、选择及撤销／重做。截图可粘贴或经图片工具添加。
- “事实记录”保留原有节点和事实修订审计；“加入尚未上板的事实”将事实及来源转为画布快照，已有节点不重复插入。自由编辑快照不会改写原始事实。
- “添加卷宗／知识库引用”可搜索本案卷宗、知识库文档来源及知识笔记／法条／摘录；文件引用保存所属案件、文件 ID 和可选页码（不填页码也可正常打开）；笔记引用保存条目 ID。卡片链接打开原件或笔记。
- 案件列表工作区及详情入口显示已保存画布 PNG 预览。
- 画布与截图保存于现有加密数据库；自动保存和手动保存显示状态。比较修订号防止不同窗口互相覆盖；保存失败时阻止路由离开，并可导出当前画布自行合并。
- 保留最近五次内容变更的场景用于恢复；恢复本身再次保存版本。仅移动视角不会挤掉内容历史。画布可导出 `.excalidraw`。
- 字体随应用本地打包；关闭在线 AI、网页嵌入和在线导出。完整数据库备份包括场景与图片。

## 人工复核路径

1. 在列表选择一个案件，打开其白板／详情再返回，核对仍是同案；从关联案件及日历打开另一案，核对标题、身份和子页面。
2. 同案创建两次庭审；程序事项中分别登记两份传票并关联庭审和卷宗。日期相同也应保留不同记录。
3. 将其中一次改为延期待定，输入决定依据；检查原日期退出待开日历，统筹页出现新排期跟进，第二次庭审保持原样，修订记录可查旧日期。
4. 白板添加事实快照、手绘箭头、截图、卷宗页码引用和知识笔记引用；分别点击链接核对去向。
5. 保存返回列表检查预览，重新打开检查图片及布局；修改后恢复上一版本，确认当前版本仍可从历史找回。
6. 从详情点击“人员”“事实白板”后刷新／返回，核对标签不跳回总览。给文件引用分别填写页码和留空，核对均打开原文件；跨案知识库文件核对打开的是来源案件。
7. 一审胜诉后登记判决有效送达与可上诉性，核对仍保留适用的救济事项；真正结束时明确登记结案。对于历史“已完结＋胜诉”数据，应看到核对提示。

## 实际边界

- 法律规则并非全部程序的完整自动裁判系统。适用范围、送达事实及裁判可救济性需核实；没有依据的事项显示待核对。现有法条来源与适用条件见 [期限规则](procedure-deadline-rules.md)。
- 多轮文书与庭审以引用关联；登记延期通知不直接更改排期，用户核实决定后明确维护庭审，避免误操作。
- 已同步到外部日历的既有事件不会因本轮本地状态更新而自动删除；应在外部日历核对变更。本地未发送旧作业会取消。
- 画布事实为快照；没有实现 Obsidian 的插件脚本、实时双向块嵌入或多人协同。卷宗页码沿用现有文件页的定位提示，具体原件打开能力由卷宗模块提供。
- 场景单次保存上限 30 MiB，最近五版包含图片；大量截图会增加案件数据库和备份体积。WebDAV 白板同步在原仓库仍是未实现接口，本轮使用本地保存、画布导出与数据库备份。
