# 任务链路审阅与个人休息时段

日期：2026-09-23。源码版本 0.1.3，数据库仍为 v42，无新增期限表或截止字段。本轮未打包、安装或推送。

## 日期语义

| 信息 | 权威数据 | 修改入口与行为 |
| --- | --- | --- |
| 任务截止 | tasks.due_date；deadline 是原有兼容别名 | 创建/更新两者同步，包括显式清空；旧冲突数据读取优先 due_date |
| 工作计划 | task_plans.start_date/end_date/revision | 甘特确认保存；不改任务截止或案件期限 |
| 具体工作时段 | calendar_events，task_id 可关联任务 | 日/周时间块；与日期级计划分开，不由计划条推算具体工时 |
| 法定期限 | case_deadlines 与程序规则投影 | 本次未改变计算规则；个人请假不会顺延法律期限 |

## 审阅发现及处置

1. 任务列表没有独立计划字段，今天/即将/跨日/下一步筛选继续读取旧开始日。现由 TaskDto 统一返回 planDefined、plannedStartDate、plannedEndDate、planRevision；原生今日查询、前端筛选、规则推荐读取同一计划语义。清空计划保留标记，不回退旧跨度。
2. 甘特保存仅发 plan 事件，其他任务消费者可能不刷新。现同时发 task:changed，已有任务列表、首页、案件视图、编辑器订阅均收到通知；通知中心还订阅任务、日程、休班变更。
3. 快捷编辑只写 dueDate，旧 deadline 可能残留，清空截止后可能再次被旧字段补回。更新时统一兼容字段（包括 NULL）；日历、统计、搜索及 AI 引用统一优先读取 dueDate。
4. 日历编辑曾用开始日填补空截止日，单纯保存可能制造截止。现保留实际空值。已有独立计划的旧开始日输入禁用，旧改期 API 拒绝无效分叉，提供甘特入口。
5. 独立计划的日期与截止不同，时间线/年历可能漏掉截止。现保留独立截止投影；年历同一天仍按任务 ID 去重。日/周显示截止具体时间，不把 dueTime 当成计划起点。
6. 案件列表、案件步骤和任务行增加计划摘要与截止区分。
7. 重复任务按原重复规则平移独立计划；没有截止的任务不凭空生成截止。已编辑下一实例的计划通过原审计哈希保护，不随撤销本次完成被删除。
8. 接手补审：任务列表「移至今日」原先仍写旧开始日且无计划守卫，与稍后安排不一致；现与快捷改期一样提示去甘特确认。
9. 接手补审：日历读计划原先只看 `list_task_plans`，计划接口失败时会退回旧开始日跨度。现优先任务 DTO 的 `planDefined/planned*`，与任务列表、筛选同一语义。
10. 接手补审：半天请假当天被当成整日休息，不再向下扫描连续休息段，次日全天假的事项可能漏提醒。连续段扫描改为仅在「今天不是全天休息」时扩展，并新增回归测试。

## 休息时段

个人设置仍使用 personal_calendar_days；可选全天、上午 09:00–12:00、下午 13:00–18:00 或自定义时间。预设时间可继续修改；旧数据没有起止时间即全天，兼容旧个人上班记录。一天保留一个个人安排，保存明确替换该日已有安排；跨日分别添加。

服务端校验真实日期、时间配对、HH:MM、结束晚于开始及日内范围；结束允许 24:00。全天个人覆盖维持旧行为；部分休息只覆盖该时段，不抹掉法定整日休息。个人上班时段仅从个人可用时间中扣除对应休息，不改法定日历。

日/周时间轴按真实起止画底纹；月/年紧凑标记为「时休」，提示完整时间；时间线、排期和甘特读同一数据，部分休息不标作整日不可用，也不算作完整空闲日。主题色与法定/个人实线虚线区分保留。

提醒按半开区间 [开始, 结束) 判断。下午请假不误报已明确结束的上午日程；跨越开始时刻的工作会提醒，恰在休息结束时开始的工作不冲突。日期级计划、无具体时间的截止提示核对；只有开始时间而结束未知的日程/庭审保守提示可能重叠。休息前一天仍检查当日待办及后续连续休息安排。提醒依赖应用运行，不是退出后的系统闹钟。

## 保留边界

甘特仍是日级计划，不推算每天实际占用小时，和关联日程时间块是不同粒度。一天只设置一个个人休息时段；自动资源容量、同日多个离散请假时段与跨日批量休息不在本轮。远端真实服务、正式发行包、系统后台唤醒未重新验收。
