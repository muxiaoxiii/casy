# 数据、网络与安全边界

核对日期：2026-09-22。本文件说明技术实现，不新增商业许可条件；历史 EULA 和隐私文本原文保留在 Archive。

## 本地数据

[runtime_paths.rs](../src-tauri/src/runtime_paths.rs) 定义位置：默认数据库在系统应用数据目录的 `Casy` 下；卷宗/模板/导出基于 `Documents/Casy` 或配置的工作区；macOS 日志默认 `~/Library/Logs/Casy`。测试或 `--profile-dir` 使用独立目录。

数据库使用 SQLCipher。新资料库密钥默认保存在本地密钥文件，Unix 权限 0600；设置提供显式钥匙串备份。旧库缺失可用本地密钥时尝试钥匙串恢复，不应生成新密钥覆盖旧库。因此不能描述为“只有钥匙串保存密钥”或“当前用户权限下其他程序绝不可能读取”。

OCR 原图、派生件、Markdown、图片目录和导出文档是普通文件，不因数据库加密而自动加密。清理或迁移时要同时考虑文件与数据库引用。

## 网络与外部内容

| 能力 | 可能流向 | 条件 |
| --- | --- | --- |
| AI / 远程嵌入 | 配置的模型服务商 | 相关功能调用；本地模型与远程 profile 要区分 |
| 飞书 | 飞书 API、消息、任务、多维表格 | 配置和对应操作/同步任务 |
| WebDAV / CalDAV | 用户服务器 | 配置、手动/后台同步 |
| IMAP / SMTP | 用户邮件服务器 | 邮件监听/发送能力启用 |
| 送达下载 | 对应法院服务地址 | 用户触发的送达处理 |
| MCP | 本地接口及其已授权客户端 | 服务启用、认证与具体工具权限 |
| 更新与资源准备 | 更新站点；开发构建时模型/依赖来源 | 更新检查或开发构建阶段 |

没有在本轮发现独立的遥测上传实现，但未进行网络抓包审计，不能声称已证明“只有三种网络请求”。旧 [PRIVACY.md](Archive/2026-09-22/compliance/PRIVACY.md) 的绝对表述与当前邮件/WebDAV等实现不一致，正式分发前需审定。

AI 写操作经提案、确认与确定性命令；配置读取优先返回 configured/迁移状态，实际调用才读取密钥。其实现需要持续测试，不等于所有第三方服务行为均由 Casy 控制。

## 备份与恢复

- [backup.rs](../src-tauri/src/commands/backup.rs)：数据库一致性快照及完整性校验；单独 `.db` 不包含所有附件。
- [portable_backup.rs](../src-tauri/src/commands/portable_backup.rs)：密码加密完整档案、文件清单与哈希、附件路径迁移、维护模式和恢复前保护副本。
- 文档处理进行中有备份/恢复限制；符号链接、缺失原件或清单不一致可能使完整备份失败，应展示原因。
- 卸载应用不等于删除资料库、卷宗、导出或日志。旧隐私文本关于“一键彻底删除全部数据”的路径未经本轮证实，不作为当前保证。

## WebDAV 完整备份与旧快照边界

旧版数据库同步只上传通过校验的 SQLCipher 快照，不上传数据库密钥。下载先用本地密钥校验，再通过维护锁、恢复前快照和回滚路径替换资料库。密钥不匹配或损坏的远程文件不会修改本地密钥或数据库。新设备须先通过完整加密备份迁移；WebDAV 快照不包括附件，也不是增量多主合并协议。

配置、最近连接结果和最近成功同步时间分别显示；本地是否有未上传更改尚不能可靠推断。启动检查仅检查版本，冲突由用户决定。历史版本上传的远端 `.key` 文件不会被新版自动删除，应由资料库所有者核查已有服务器存储。

### 2026-09-23 完整备份入口

设置 → WebDAV 备份直接提供“备份全部数据 / 恢复全部数据”。复用本地 `.casy` 完整备份格式：数据库（案件、任务、笔记、设置等）、卷宗原件、附件和本地文档产物，使用用户输入的独立密码加密。系统钥匙串中的外部服务凭据不随包迁移，新设备需重新配置。

远程文件为 `casy-full-backup.casy`，与旧 `casy.db` 分开。上传先使用唯一临时名，成功后通过 WebDAV MOVE 替换正式文件；服务器必须支持 PUT / GET / MOVE。当前只保留远端最新一份，未实现多版本选择、条件提交或自动多主合并。失败时尽力删除临时上传，未到 MOVE 阶段不覆盖已有完整备份。

网络传输按块读取本地文件/写入下载文件；上传按实际消费数据块重置 300 秒无进展预算，下载按响应/数据块设置等待上限；不使用固定总时长的前端超时。临时档案在本机 backups 目录，传输结束后清理，备份本身不递归包含备份目录。

恢复需要在对话框明确确认覆盖；密码认证、附件哈希验证、路径迁移、数据库换钥和恢复前加密保护备份完成后才替换当前数据库。原始文件保留；保护备份为本机 backups 下的 `pre-restore-*.casy`，使用本次恢复密码，可在“数据备份 → 从完整备份恢复”选择。恢复后退出并重启应用。完整档案不要求原设备与新设备共用数据库密钥。

## 个人调休与法定日历

`personal_calendar_days` 独立保存在 settings 表，参与完整备份；后端验证真实日期、类型、备注长度与日期唯一性。六种日历视图同时显示法定安排和个人安排，允许同一天存在不同来源的标记。个人调休只用于个人排期，不写入 `holidays_json`，不会导致诉讼期限按个人假期顺延。旧节假日 JSON 没有个人来源元数据，仍按原法定日历导入处理；不能根据名称猜测个人调休。

休息工作提醒由后端读取真实任务、日程、期限和待开庭，写入 `notifications`，不外发。提醒采用每日事项标识去重，保留用户的已读/已处理状态，重新检查会撤下已完成、改期或不再符合休息安排的记录。应用未运行时无定时提醒；这是排期辅助，不能代替法律期限提醒。

## 独立任务计划

schema v42 的 `task_plans` 随数据库快照纳入完整备份。计划起止与任务开始/截止日期分开；写入检查任务未完成且未删除、起止有效且跨度不超过 3660 天，并比较 expectedRevision。取消计划保留 NULL 起止及递增修订号，阻止旧请求覆盖重新创建的计划。计划与 task_events 审计在同一事务提交，审计失败回滚计划。休息日提醒读取独立跨度，同时保留原任务截止日的提醒。
