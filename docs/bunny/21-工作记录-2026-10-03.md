### 2.2 加宽 Windows 刷盘守护

原守护（codex 写的）只扫 4 个文件、只匹配一种链式写法：

```js
for (const file of ['commands/inbox.rs','commands/backup.rs','commands/portable_backup.rs','db/mod.rs'])
```

## 三、我判断错并撤销的一次改动

接手时我看到 8 处 `let _ = ....keep();`，认定是"吞掉落盘失败 → 文件被删 → 报告成功"的静默损坏，
并改了 5 个文件。

**这是错的。** `tempfile 3.27` 的 `TempDir::keep()` 签名是：

```rust
pub fn keep(mut self) -> PathBuf   // tools/casy-doc-engine 依赖的同一版本
```

**返回 `PathBuf` 而非 `Result`，不会失败**——它只是关掉 drop 时的清理。
`let _ =` 丢弃的只是一个用不到的路径值，**没有错误可吞**。

我把旧版/别的库的 fallible 签名记混了。编译器当场报错（`no method named map_err found for
PathBuf`）才暴露出来。**已全部还原为原样**，只保留 §2.1 的真实修复。

顺带查证结论：`portable_backup.rs:709` 那处 `staging.keep()` 更是无害——
真正用于替换的 `next` 已在第 702 行 `fs::copy` 拷出 staging，与临时目录无关。

> **教训**：这次和 10-02 的 `sequenceOrder` 是同一个错误的两个方向。
> 那次是拿几轮之前的旧行号当当前事实；这次是没核实第三方 API 签名就下结论。
> **引用外部 API 行为前先读它的源码。**
