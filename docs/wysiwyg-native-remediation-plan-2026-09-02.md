# WYSIWYG 与原生桌面验收修复计划

> 日期：2026-09-02  
> 状态：执行中（阶段记录见 `docs/wysiwyg-native-remediation-walkthrough-2026-09-02.md`）  
> 依据：`docs/global-benchmark-inspirations-walkthrough-2026-09-01.md`、当前脏工作区代码、2026-09-02 实际检查结果  
> 范围：知识库 WYSIWYG、双链/历史、文书生成编辑与导出，以及受本批改动影响的桌面 UI 回归

## 一、结论与验收原则纠正

本批已经建立 Markdown 与 WYSIWYG 的基本框架，但目前不能标记为“完成”或“可合入”。已确认存在预览注入风险、Markdown 图片丢失、最后输入丢失窗口、案件/模板与渲染结果错配、证据链接导出契约不一致等问题；编辑后 DOCX 导出也尚未在真实 Tauri 应用中完成端到端验证。

从本计划开始，Casy 的验证分为四层，证据强度不得混用：

1. **转换与业务单测**：证明局部算法和数据契约正确。
2. **组件与集成测试**：证明 Vue/Tiptap 生命周期、IPC 参数和状态切换正确。
3. **真实 Tauri 运行验证**：证明 WebView、Rust IPC、数据库、文件系统、系统对话框和窗口布局实际可用。
4. **产物验证**：证明导出的 DOCX、保存的草稿、版本历史和应用重启后的持久化结果正确。

浏览器 Mock 预览今后只允许用于纯前端布局的快速迭代和低成本辅助定位，不得作为以下结论的依据：

- “功能已接线”或“真实数据可保存”；
- “文件导出可用”；
- “系统窗口、弹窗、拖拽、快捷键可用”；
- “最小窗口尺寸没有遮挡、滚动或卡死”；
- “可以发布”或“本批已完成”。

如果真实 Tauri 应用无法启动，相应功能必须记录为“阻塞/未验证”，不得退回浏览器 Mock 后改判为通过。

## 二、当前已确认问题

| ID | 级别 | 问题 | 影响 | 当前证据 |
|---|---|---|---|---|
| WYS-01 | P0 | `mdToSafeHtml` 使用正则清洗，未拦截未加引号或实体编码的 `javascript:` | 知识预览进入 `v-html`，存在脚本/危险链接注入风险 | 已在实际渲染结果中复现危险 `href` |
| WYS-02 | P0 | Tiptap 未注册图片节点 | Markdown 图片进入富文本后不可见，继续编辑会永久删除图片语法 | 已实际复现 |
| WYS-03 | P0 | 400ms 防抖在组件卸载时直接取消 | Wiki 跳转、路由切换等未先触发 blur 的路径可能丢失最后输入 | 生命周期代码确认，现有测试未覆盖 |
| DOC-01 | P0 | 案件/模板 `v-model` 先变化，放弃重渲后不回滚选择 | 旧文书可能被保存到新案件或新模板名下 | 状态流代码确认 |
| DOC-02 | P1 | EvidenceLink 输出 `data-evidence-link`，导出逻辑查找 `data-type="evidence-link"` | 证据引用不会生成脚注和参考列表 | HTML 契约与选择器直接矛盾 |

| DOC-04 | P1 | 保存为草稿后 `hasEdits` 仍只与原始渲染结果比较 | UI 继续显示“尚未保存”，重复点击可能生成重复草稿 | 状态定义确认 |
| DOC-05 | P1 | 模板/案件连续切换没有请求身份或竞态保护 | 较慢的旧渲染可能覆盖较新的选择 | 当前 composable 只有共享 `renderResult` |
| UI-01 | P1 | 当前 WYSIWYG 只在浏览器 Mock 做过主要可视检查 | Tauri 窗口、真实数据、弹窗、滚动、输入法和文件导出状态未知 | 验证边界不足 |
| DOCS-01 | P2 | walkthrough 声称“已知边界均不丢内容”且章节顺序错误 | 文档结论高于实际证据 | 图片丢失已推翻该表述；第七节位于第六节总结前 |

## 三、目标状态

完成本计划后必须满足：

- 知识笔记以 WYSIWYG 为默认编辑方式，Markdown 仍是稳定、可恢复的数据源；
- 支持的内容在源码、富文本、分栏和预览之间往返不丢失；
- 暂不支持的内容必须原样保留或显式阻止破坏性回写，禁止静默删除；
- Wiki 双链、历史恢复、OCR/PageIndex 导入内容在保存、切换、重启后保持一致；
- 文书的案件、模板、渲染结果和草稿具有同一组不可混淆的身份信息；
- 编辑后 DOCX 由原生后端导出，不依赖浏览器侧 Node 兼容垫片；
- 真实 Tauri 应用在目标窗口尺寸下没有遮挡、不可滚动区域、弹窗失焦或无法操作的控件；
- walkthrough 只记录已由相应层级证据验证的能力。

## 四、实施阶段

### Phase 0：建立可重复的原生测试环境

目的：在不污染用户真实数据库、模板和导出目录的情况下反复启动 Tauri 应用。

1. 为 debug/test 构建增加隔离配置：
   - `CASY_TEST_DATA_DIR`：数据库、密钥文件和测试附件目录；
   - `CASY_TEST_TEMPLATE_DIR`：测试 DOCX 模板目录；
   - `CASY_TEST_EXPORT_DIR`：测试导出目录；
   - 仅在 `debug_assertions` 或测试构建中接受这些覆盖，正式构建继续使用原路径。
2. 测试配置不得复用正式 Keychain 项；测试密钥存放于隔离目录。
3. 新增固定测试夹具：
   - 至少两个不同名称、不同字段的案件；
   - 两个 DOCX 模板；
   - 包含中英文、表格、任务列表、WikiLink、图片、代码块的 Markdown 笔记；
   - 包含 EvidenceLink 的文书草稿；
   - 一份 OCR/PageIndex 导入树。
4. 增加原生测试启动说明，明确启动命令、测试目录、窗口尺寸和清理方式。

**完成标准**：可以启动一个与用户真实数据完全隔离的 Casy Tauri 实例，退出和重启后测试数据仍可验证持久化。

### Phase 1：修复知识库安全与内容保真

#### 1.1 使用 DOM 白名单消毒

- 引入 DOMPurify 或等价的 DOM 级白名单方案，删除自制正则清洗器。
- 明确允许的标签、属性和协议；WikiLink 只允许所需的 `data-wiki-link`、`data-title`。
- `href/src` 只允许批准的协议；禁止 `javascript:`、危险 `data:`、事件属性、SVG/MathML 可执行面和样式注入。
- `mdToHtml` 仅供受控编辑器载入；所有 `v-html` 必须使用安全输出。

测试至少覆盖：未加引号协议、大小写混淆、HTML 实体编码、换行混淆、SVG、事件属性、嵌套危险标签和正常 WikiLink/GFM。

#### 1.2 补齐图片和未知内容保留

- 为 Tiptap 注册图片节点，保留 `src/alt/title` 并补齐 Markdown 双向规则。
- 本地优先：粘贴/拖入图片时复制到 Casy 管理的附件目录，再保存稳定资源引用；不得依赖临时 blob URL。
- 远程图片不得因为 CSP 静默不显示：要么导入本地，要么显示明确的外部资源占位提示。
- 对暂不支持的原始 HTML 建立 `RawHtmlBlock`/只读占位节点，保存原文；不得在第一次富文本编辑时删除。
- 给“切换到富文本将导致不可表示内容变化”的情况提供阻止或明确确认，但优先实现无损占位。

#### 1.3 修复编辑器同步和切换时序

- `MarkdownWysiwygEditor` 暴露 `flushAndGetMarkdown()`，返回当前编辑器的权威 Markdown。
- 父级在切换笔记、WikiLink 导航、历史恢复、路由离开和关闭窗口前，先获取旧笔记内容，再保存旧笔记，最后替换 `selectedId/draft`。
- 禁止在 `onBeforeUnmount` 中向已经切换到新笔记的 v-model 盲目回写。
- 保存请求绑定 `noteId + revision`；旧请求完成时不得把新笔记标记为已保存。
- 失败时保留 dirty 状态并给出可重试提示。

测试至少覆盖：输入后 0–400ms 内点击 WikiLink、切换列表项、恢复历史、切换路由、连续切换两次以及保存失败重试。

#### 1.4 双链、历史和 OCR/PageIndex 回归

- WikiLink 点击必须先保存来源笔记，再跳转目标笔记。
- 历史恢复后同时验证正文、WikiLink 关系和反向链接。
- OCR/PageIndex 导入后验证层级、页码、Markdown、图片/附件引用和搜索命中。
- 应用重启后重复检查，排除只存在于前端内存的假接线。

**Phase 1 完成标准**：恶意内容不能进入危险 DOM；受支持 Markdown 往返无损；未知内容不静默删除；快速切换和重启不丢最后输入。

### Phase 2：修复文书身份一致性与原生导出

#### 2.1 将选择状态改为提交式状态

- 区分 `pendingTemplate/pendingCase` 与 `committedTemplate/committedCase`。
- 有未保存编辑时，先确认，再提交新选择；取消后 UI 和内部状态都恢复旧值。
- `renderResult` 改为带身份的结构：`templateId + caseId + requestId + html + text`。
- 只接收当前 requestId 的渲染结果，丢弃过期响应。
- 保存草稿和导出前校验当前选择与 renderResult 身份完全一致，否则拒绝执行。

#### 2.2 修复草稿保存语义

- 保存成功后记录 `lastSavedHtml` 和 `draftId`，脏状态与最近一次保存内容比较，而不是始终与模板原始内容比较。
- 已存在 draftId 时更新原草稿；只有用户明确“另存为新草稿”时才新建。
- 切换页面、案件或模板前对未保存草稿使用同一套确认逻辑。

#### 2.3 统一 EvidenceLink 契约

- 以 `EvidenceLink.ts` 的 `span[data-evidence-link]` 为唯一 HTML 契约。
- 抽取共享序列化/导出函数，禁止不同页面复制选择器字符串。
- 导出后验证正文脚注编号、参考证据列表、label、anchor、targetId 和 caseId。
- 对损坏或缺字段的证据链接明确降级为可读文本并记录警告，不能静默消失。

#### 2.4 将编辑后 DOCX 导出迁至 Rust

前端不再直接调用 `html-to-docx`。采用下列确定方案：

1. LegalEditor 输出受控的 Tiptap JSON/`EditedDocumentIR`，而不是把任意 HTML 直接交给导出器；
2. IR 至少覆盖段落、标题、文本标记、引用、代码块、有序/无序/任务列表、表格、图片和 EvidenceLink；
3. Rust 新增 `export_edited_docx` 命令，使用 Rust DOCX 生成库构造 OOXML；
4. 输出路径、覆盖确认和打开文件均通过 Tauri 原生能力处理；
5. 不支持的节点返回明确错误，禁止生成看似成功但内容残缺的文件；
6. 未编辑的模板导出继续使用现有 `export_docx`，但两条路径共享输出结果和错误契约。

导出验证必须包含：

- ZIP/OOXML 结构检查；
- 正文、中文字体、列表、表格、图片和证据脚注内容检查；
- 使用 Word 和至少一个兼容应用（WPS 或 LibreOffice）实际打开；
- 关闭应用后文件仍可打开，且文件大小、页数和核心内容合理。

**Phase 2 完成标准**：案件/模板不会错配；保存后 dirty 状态正确；EvidenceLink 正确导出；编辑稿在真实 Tauri 应用中导出并由 Word/WPS 成功打开。

### Phase 3：真实 Tauri UI 与交互验收

本阶段不使用浏览器 Mock 作通过判定。使用实际 Tauri 窗口，通过桌面控制或人工走查操作并保留截图、日志和结果文件。

#### 3.1 固定窗口矩阵

| 尺寸 | 目的 |
|---|---|
| 800×600 | 配置允许的最小窗口，检查遮挡、按钮不可达、双重滚动 |
| 1024×720 | 默认窗口，作为主要验收尺寸 |
| 1440×900 | 常规桌面，检查过宽留白、编辑区比例和信息密度 |

每个尺寸检查：侧栏展开/折叠、系统缩放、浅色/深色主题、中文输入法、长标题、长标签、长文档和弹窗。

#### 3.2 知识库操作清单

- 打开知识库并选择真实数据库中的笔记；
- 富文本/源码/分栏/预览来回切换；
- 输入中文、英文、标点、组合输入文字；
- 插入并编辑图片、表格、任务列表和 WikiLink；
- 快速切换笔记、点击 WikiLink、恢复版本、撤销/重做；
- 验证双链面板和历史面板滚动、空状态、错误状态；
- 导入 OCR/PageIndex，搜索导入内容并跳转页码；
- 关闭并重启应用，确认正文、链接、图片和历史仍在；
- 检查工具栏是否换行遮挡、编辑区是否错误滚动、焦点是否丢失、UI 是否卡死。

#### 3.3 文书操作清单

- 使用真实测试模板和两个测试案件完成预览；
- 在 WYSIWYG 中修改标题、正文、列表、表格、图片和证据链接；
- 保存草稿并在文书工坊重新打开；
- 有未保存修改时切换案件/模板，分别验证取消与确认；
- 连续快速切换，确认旧请求不会覆盖新结果；
- 导出未编辑模板稿和编辑稿；
- 通过系统文件对话框定位文件，并用 Word/WPS 打开；
- 验证脏点、加载态、错误提示、重复点击防护和返回导航。

#### 3.4 应用外壳回归

本批依赖和共享组件变化后，至少回归：

- 设置页面能打开、能关闭、内容可滚动；
- 收件箱在默认和最小窗口下布局正常；
- 任务列表至少能新建、编辑、完成和打开关联对象；
- 知识库、文书工坊、案件、任务和设置之间连续切换不白屏、不冻结；
- 开发日志没有未处理异常、组件解析失败或持续刷屏。

每个问题记录：应用版本/commit、脏工作区摘要、窗口尺寸、主题、复现步骤、预期、实际、截图、日志位置和处理结论。

**Phase 3 完成标准**：上述矩阵全部实际执行；没有 P0/P1 UI 问题；所有关键操作均由真实 Tauri IPC 和真实文件系统完成。

## 五、测试矩阵与最低用例

| 层级 | 必测内容 | 通过证据 |
|---|---|---|
| Markdown 单测 | GFM、WikiLink、图片、特殊字符、未知 HTML、恶意 HTML | 精确往返和安全断言 |
| Vue 组件测试 | 初始化、输入、防抖、flush、卸载、切换、错误保存 | 组件挂载测试与假时钟 |
| Rust 单测/集成 | IR 校验、OOXML 生成、路径安全、EvidenceLink、图片 | 生成文件结构与内容断言 |
| Tauri 集成 | 真实 IPC、数据库保存、模板渲染、草稿重开 | 隔离 profile 中的持久化结果 |
| 原生 UI | 三种窗口、主题、输入法、弹窗、滚动、快捷键 | 截图、日志和逐项检查表 |
| 产物 | 编辑/未编辑 DOCX、Word/WPS 打开 | 文件、结构检查和打开结果 |

以下场景任何一个失败，都不得把本批标为完成：

1. 图片或未知内容在富文本编辑后消失；
2. 最后一次输入在快速切换后丢失；
3. 危险 HTML 进入可执行 DOM；
4. 草稿的 caseId/templateId 与渲染来源不一致；
5. EvidenceLink 导出缺少正文标记或参考列表；
6. 编辑 DOCX 只能在浏览器 Mock 中“看起来能导出”；
7. 800×600 或 1024×720 下关键操作按钮不可达；
8. 设置、收件箱、任务或知识库出现白屏、冻结或无法操作。

## 六、执行顺序与提交边界

建议按以下顺序实施，前一阶段未过门禁不得进入后一阶段：

1. Phase 0：隔离 profile 与固定夹具；
2. Phase 1.1–1.3：安全、图片、未知节点和保存时序；
3. Phase 1.4：双链/历史/OCR PageIndex 回归；
4. Phase 2.1–2.3：身份一致性、草稿和 EvidenceLink；
5. Phase 2.4：Rust 编辑稿 DOCX 导出；
6. Phase 3：真实 Tauri UI 全矩阵；
7. Phase 4：全量门禁、walkthrough 和交付说明。

提交应按上述阶段拆分，禁止把安全修复、导出重构、UI 调整和文档更新塞入一个不可审阅的大提交。当前工作区已有大量未提交改动，实施前必须先记录并保护现有 diff；不得使用会丢弃用户修改的 checkout/reset 操作。

## 七、完成定义

只有同时满足以下条件，本计划才能标记完成：

- WYS-01 至 WYS-03、DOC-01 至 DOC-05 全部关闭并有回归测试；
- 自动门禁全部通过；
