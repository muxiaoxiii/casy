# Casy 0.2.0 细节打磨规格书 · 参照律智荟 OA 说明书

核对日期：2026-10-13。配套 `docs/UPDATE_PLAN_0.2.0.md`（架构与分期）。
**本文件只谈细节打磨**：架构按既定方案不动，不新增模块级能力。

> **2026-10-13 两项确认**：
> ① **协作内容一律不做**。清单里唯一带协作语义的是"待认领池"，已改为单用户的**待定归属**（I5）；学习记录里提到的参与人一键转化、协同日程推送等**仅作记录，不实施**。
> ② **不存在"harness 化"这回事**。OCR provider 抽象（内置引擎/Myna）、AI profile、embedding 档位从一开始就是 harness 结构，没有要"化"的东西。原 §3 那 7 项本质是"这个 harness 对用户不可见"（`degraded` 是死分支、当前 provider 看不到、模型档位无入口、配额不显示），属于普通打磨项，已并入正文，不再单列。

## 0. 边界声明（先划清楚，避免跑偏）

| 做 | 不做 |
|---|---|
| 把我们**已有模块**的交互细节、状态机、反馈、边界提示做到位 | 不新增模块（不建审批流、不建协作、不建报表体系、不建权限体系） |
| 把 OA 说明书里**对应到我们模块**的具体做法记录下来当学习材料 | 不照搬它的组织级能力（多租户/角色/工作流/待认领审批链） |
| 把已有 harness（OCR provider / AI profile / embedding / 工具策略）的**可见性、可观测性、降级反馈**做到位 | 不引入新的 AI 能力面 |
| 每条打磨项都落到"用户能感觉到的差异" | 不做纯内部重构（除非它是某个打磨项的前置） |
