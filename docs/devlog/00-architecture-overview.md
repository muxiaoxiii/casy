## 一、项目概述

**Casy** 是基于 Tauri 构建的本地优先法律案件管理应用，面向专利律师，定位为「全流程秩序引擎」。

### 核心定位

> Casy 是专利律师的「全流程秩序引擎」——它既不是案件管理工具，也不是 GTD 工具，更不是知识库，而是三者合一的一个秩序系统。

### 设计目标

| 目标 | 说明 |
|------|------|
| **秩序** | 打开就知道现在该做什么、在等什么、卡在哪 |
| **流动** | 信息沿着"捕获 → 厘清 → 组织 → 执行 → 回顾"自然流转 |
| **克制** | 不堆功能，不炫技，拒绝情绪价值装饰 |
| **成长** | 系统从使用中学习，主动推荐，与律师一同成长 |

## 四、八大设计原则

### 原则一：案件即流程

案件是天然的线性流程，只有 `blocked=0` 的行动对用户可见。

### 原则二：时间双轨

每个任务有双轨：`start_date`（什么时候进入视线）+ `due_date`（什么时候必须完成）。

### 原则三：先捕获，后整理

任意页面都可触发极简捕获（Cmd+T/E/N/I），捕获结果默认进收件箱。

### 原则四：数据有限，视图无限

四大元信息（案件/任务/领域/知识），透视由字段推导而非独立存储。

### 原则五：克制即优雅

拒绝装饰性功能，信息按需披露，视觉克制。

### 原则六：主动智伴

AI 越用越懂你，双路径铁律（去 AI 路径 / 含 AI 路径）。

### 原则七：数据蒸馏与外置记忆

三层记忆架构（L1 原始 / L2 提炼 / L3 知识库），蒸馏循环。

### 原则八：双向开放

MCP Server 对外暴露，MCP Client/Skill Runner 对内引入。

## 五、数据模型

### 5.1 四大元信息

```
                    ┌─────────────┐
                    │  领域 Area   │  ← 长期业务方向
                    └──────┬──────┘
                           │ belongs_to
                    ┌──────┴──────┐
                    │  案件 Case   │  ← 项目（顺序流程）
                    └──────┬──────┘
                           │ belongs_to
              ┌────────────┴────────────┐
              │                         │
     ┌────────┴────────┐       ┌────────┴────────┐
     │   任务 Task      │       │   知识 Note      │
     │  action/waiting  │       │  6 种职能分类     │
     └────────┬────────┘       └────────┬────────┘
              │                         │
              └───────── references ────┘
```
