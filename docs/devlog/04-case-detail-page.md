## 一、实现概述

案件详情页从简单的字段平铺重构为「项目书」结构，帮助律师快速了解案件全貌和下一步行动。

## 二、页面结构

### 2.1 案件概要

**内容**:
- 案件名称
- 案号
- 客户名称
- 法院
- 案件类型（计算型/探索型/成长型）
- 轨道徽章（民事诉讼/专利无效/行政诉讼）

**设计**: 紧凑布局，一目了然

### 2.2 项目总览

**三栏布局**:

1. **案件目标**
   - 30字内概括
   - 可编辑
   - 点击编辑按钮修改

2. **任务统计**
   - 总计/待办/完成/逾期
   - 数字突出显示

3. **项目进度**
   - 环形进度条
   - 百分比显示

### 2.3 下一步行动

**设计**: 高亮区块，引导用户行动

**内容**:
- 下一步行动任务名称
- 截止日期
- 预估时间
- 完成按钮

**交互**:
- 点击卡片 → 编辑任务
- 点击完成 → 完成任务并解锁下一步

### 2.4 项目流程（顺序项目）

**设计**: 步骤列表，清晰展示流程

**内容**:
- 步骤名称
- 状态标签（进行中/已锁定/已完成）
- 等待提示（已锁定时）

**交互**:
- 点击步骤 → 编辑任务
- 点击完成 → 完成步骤并解锁下一步

**顺序项目机制**:
- `sequential = 1` 标记为顺序项目
- `blocked = 0` 表示可执行
- `blocked = 1` 表示等待前置步骤
- `sequence_order` 控制顺序

### 2.5 三轨状态

**设计**: 卡片网格，每轨独立显示

**内容**:
- 民事诉讼状态
- 专利无效状态
- 行政诉讼状态

**状态标签**: 使用语义色

### 2.6 关联资源

**设计**: 三栏卡片网格

**内容**:
- 待办任务数
- 案卷文件数
- 关联知识数

**交互**: 点击卡片 → 跳转到对应模块

### 2.7 动态轨迹

**设计**: 时间线布局

**内容**:
- 最近10条动态
- 事件摘要
- 事件日期

**交互**: 点击事件 → 查看详情

## 三、核心功能

### 3.1 顺序项目自动解锁

**机制**:
1. 完成当前步骤
2. 系统自动查找下一个 `blocked = 1` 的任务
3. 将下一个任务的 `blocked` 设为 `0`
4. 显示解锁提示

**代码逻辑**:
```javascript
async function unlockNextTask(completedTask) {
  const nextTask = tasks.value.find(t => 
    t.caseId === caseId.value && 
    t.sequential && 
    t.blocked && 
    t.sequenceOrder > completedTask.sequenceOrder
  )
  
  if (nextTask) {
    await tauriCallSafe('update_task', {
      data: { id: nextTask.id, blocked: 0 }
    })
    nextTask.blocked = 0
    ElMessage.success(`已解锁：${nextTask.taskName}`)
  }
}
```

### 3.2 案件目标编辑

**机制**:
- 默认显示案件目标
- 点击编辑按钮进入编辑模式
- 30字限制
- 回车或点击保存按钮保存

### 3.3 任务统计计算

**逻辑**:
- 总计: 所有任务数
- 待办: 未完成任务数
- 已完成: 已完成任务数
- 逾期: 未完成且截止日期早于今天的任务数

## 四、设计原则遵循

### 4.1 原则一：案件即流程

- 顺序项目列表展示案件流程
- 只有 `blocked = 0` 的任务可执行
- 完成一步自动解锁下一步

### 4.2 原则五：克制即优雅

- 信息按需披露
- 视觉克制
- 无装饰性元素

### 4.3 原则四：数据有限，视图无限

- 案件详情是多个数据源的聚合视图
- 关联资源是同一份数据的不同视图
