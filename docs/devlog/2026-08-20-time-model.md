# 时间模型整体打通（设计哲学 §7 时间分配）

> **日期**: 2026-08-20
> **背景**: 用户批评"一条条修没整体思维"——日历列表与待办无综合显示、拖拽只到天不到时间点、任务无具体时间点。
> 本轮把"时间"作为整体模型一次性打通：日期（date）+ 时间点（due_time HH:MM）两个维度统一。

---

## 一、数据模型（schema v13）

- `tasks.due_time TEXT`（HH:MM 具体时间点）+ 索引
- 幂等迁移：ADD COLUMN 走条件补列段（PRAGMA 探测），MIGRATIONS 只推进版本号

## 二、任务具体时间点（不再丢弃）

- **自然语言捕获**：TasksView 快速捕获解析的时间词（"3点/3点半/HH:MM"）→ `dueTime`（原注释"任务无时间字段"被剥离丢弃——已修复）
- **编辑/厘清表单**：截止日期旁加"时间点"选择（el-time-select 30 分钟步进）
- **任务卡显示**：截止日期旁显示 `HH:MM`
- **后端**：create_task / update_task 支持 `dueTime`（修复 update_task 参数序号错位）

## 三、日历综合显示（日历 + 待办合一）

- **周视图时间轴**：`getWeekDayHourEvents` 同时返回该时刻的日程事件 + 有时间点的任务（任务蓝色样式区分）——日历和待办在时间轴上综合呈现
- **月视图**：任务 chip 显示时间前缀（"14:00 会议"）
- **Forecast**：时间块分区已按任务时间排序（上一轮）

## 四、拖拽完整（改期到时间点）

- 月视图拖任务到另一天 → 改 `dueDate`（已有）
- **周视图拖到时间轴某时刻** → 改 `dueDate + dueTime`（新增 `onDropToTime`，每时间行加放置区）

## 五、验证

- `npm run build` ✅ · `cargo check` ✅ · `cargo test` ✅ 103/103

## 六、遗留/注意

- `normalizeTimeWord` 把"3点"按 24 小时制整数处理（03:00），未区分上午/下午——与日历的自然语言（有上下午处理）风格不一致，可在任务捕获里加"下午3点"→ 15:00 的时段推断
- 新建任务弹窗（newTask）暂无时间字段（编辑抽屉有）
