# 三层导航架构实现记录

> **日期**: 2026-08-18  
> **状态**: 已完成  
> **影响范围**: 前端布局、导航系统、今日面板

---

## 一、实现概述

三层导航架构将信息按重要性和使用频率分层，帮助律师快速找到「现在该做什么」。

---

## 二、三层架构

### 2.1 第一层：全局聚合（今日面板）

**位置**: 顶栏常驻

**内容**:
- 硬性日程（开庭/口审）- 红色
- 今日到期任务 - 琥珀色
- 等待超3天 - 灰色
- 需回顾案件 - 绿色

**交互**:
- 点击统计项 → 跳转到对应模块
- 刷新按钮 → 重新加载统计

**数据源**: `get_today_stats` 命令

### 2.2 第二层：核心模块（左侧侧栏）

**位置**: 左侧侧栏

**模块**:
1. 首页（蓝色）
2. 案件（绿色）
3. 任务（琥珀色）
4. 日历（红色）
5. 收件箱（灰色）
6. 知识库（紫色）
7. 文书（青色）
8. 设置（灰色）

**交互**:
- 点击模块 → 切换到对应页面
- 悬浮展开 → 显示模块名称

### 2.3 第三层：模块内 Tab

**位置**: 页面标题栏右侧

**内容**: 根据当前模块动态显示

**模块 Tab 映射**:
- 案件: 全部/我负责/等待中/已结案/按客户
- 任务: 收件箱/下一步/等待/今日/回顾/某天
- 知识库: 灵感/方法/参考/问题/经验/日志
- 日历: 月视图/周视图/预测

**交互**:
- 点击 Tab → 切换视图
- Tab 状态通过路由 query 参数持久化

## 四、后端实现

### 4.1 get_today_stats 命令

**功能**: 获取今日概览统计数据

**返回**:
```json
{
  "hardSchedule": 2,    // 硬性日程数
  "dueToday": 5,        // 今日到期任务数
  "waitingOverdue": 3,  // 等待超时数
  "needReview": 1       // 需回顾案件数
}
```

**查询逻辑**:
- 硬性日程: `hearings` 表中 `hearing_date = 今天`
- 今日到期: `tasks` 表中 `(deadline = 今天 OR due_date = 今天) AND completed = 0`
- 等待超时: `tasks` 表中 `task_type = 'waiting' AND follow_up_date < 3天前`
- 需回顾: `cases` 表中 `next_review_date <= 今天`

## 五、设计原则遵循

### 5.1 原则五：克制即优雅

- 信息按需披露：三层过滤
- 视觉克制：单主色、线性图标
- 信息密度优先：统计项紧凑排列

### 5.2 原则四：数据有限，视图无限

- 今日面板是多个模块数据的聚合视图
- 模块内 Tab 是同一份数据的不同视图

## 九、技术细节

### 9.1 前端状态管理

- 使用 `ref` 管理今日统计
- 使用 `computed` 计算模块 Tab
- 使用 `watch` 监听路由变化

### 9.2 路由集成

- Tab 状态通过 `router.query.tab` 持久化
- 切换模块时自动重置 Tab

### 9.3 响应式设计

- 侧边栏悬浮展开
- 今日面板统计项自适应
- 模块 Tab 溢出隐藏
