# Casy 视觉与数据体验审查

日期：2026-09-05

## 产品结构

- 案件继续作为主要工作对象，撤下本轮新增的独立项目导航和捕获选项。保留原有内部路由兼容性，没有新建项目数据体系。
- 客户视图由 `case_stats.byClient` 聚合；选择客户后以 `list_cases({ client, page, perPage })` 查询真实案件，支持分页并打开可编辑案件详情。
- 数据看板按案件统计，轨道图点击进入相应案件筛选；任务指标按同一日期口径下钻。

## 已修复

1. 原生首页空白：打包版 CSP 禁止 `Function`，vue-i18n 原来的消息编译器因此报错。启用库提供的 AST/JIT 模式，保留原安全策略；补齐 Vue 和路由异常到本地日志的接线。
2. 收件箱标题：普通速记曾以分类值 `other` 命名。现在依次采用显式标题、正文首个非空行、附件文件名、未命名占位，并按字符限制长度。已有记录不批量改名。
3. 案件假事实：去除概览中虚构律师、法院、书记员、专利名称和号码、固定法定日期、备忘时间等缺省值；编辑缺失字段不再自动填入诉讼身份和审级。顶部进度使用真实任务完成率；未接入节点进度的标准程序显示未确认。
4. 收件箱：统一列表与澄清表单，真实来源和时间，可编辑任务标题、期限、案件、等待对象、跟进日期、时长；窄窗口不再把提交按钮挤出视口。选中记录变化时重置澄清内容。
5. 捕获弹窗：统一基础组件、间距和主题色，支持真实案件分页响应、远程检索、关联清空、标题与日期复核、重复打开重置、部分上传失败后避免重复保存。文件选择与拖入按 Tauri 原生路径处理。
6. 任务详情：补齐类型、开始安排、等待对象和跟进日期的编辑控件，支持从首页和指标打开对应任务。
7. 图表：修复环图坐标和零值分段、折线缩放后的命中与提示框坐标、庭审相对天数；补足数据明细、加载、空态、独立失败处理。不可用指标不显示为零。
8. 日历：服务层映射原生 `eventType` 为视图字段，保留时间与案件信息。组件语言跟随应用设置。
9. 首页：移除虚构排期和固定工时、等待进度，下一步行动来自实际待办，任务勾选与编辑分离；精力负荷按填写的预计时长汇总。
10. 浏览器预览：基础速记转任务会真正写入内存测试集合，未模拟的处理动作返回失败，不再伪报已完成。预览仍不代表原生数据库。

## 验证

- 使用 `CASY_TEST_DATA_DIR=/tmp/casy-visual-qa.0qVV5p` 启动本地调试包，数据库、卷宗和日志均隔离，没有向日常案件库写入验收记录。
- 原生完整流程：新建案件 → 编辑客户 → 客户页自动聚合；捕获“明天提交视觉验收材料” → 关联案件 → 编辑标题 → 确认 → 任务列表显示正确案件和次日日期。
- 原生等待流程：速记 → 等待对象与 2026-09-07 跟进日 → 转等待任务 → 首页显示两天后跟进 → 任务详情读出相同字段。
- 原生截图检查：首页、收件箱、捕获复核弹窗、数据看板；案件概览与客户页进行可访问性树核验。默认窗口 1024×720 下收件箱表单独立滚动、底部提交保持可达。
- 浏览器辅助检查包括 1440×1000、390×844 数据看板和 1280×720 收件箱。最后浏览器重连出现 CDP 超时，后续验收在原生应用完成。
- `npm run test:unit`、`npm run build`、`npm run tauri -- build --debug --bundles app`；Rust 针对新增标题规则的单测；`git diff --check`。

## 边界与后续

- 本轮集中修复主要工作流和共享视觉基础。知识编辑器、文书工坊、系统设置等复杂工作区没有做全面重设计；暗色模式未完成逐页原生截图验收。
- OCR、真实邮箱采集、飞书同步、AI 模型输出和批量文件归档没有做外部服务端到端验收。
- 程序节点仍是标准参考序列，未与各程序完整状态历史接线，因此不显示推测的完成百分比。
- 客户按案件中填写的名称聚合；不同拼写仍会形成不同分组，没有引入独立客户主数据。
- Tauri WebView、真实 IPC 与打包 CSP 必须作为验收主路径，浏览器用于响应式与局部样式辅助。单独增加一个应用内“调试页面”不能替代这些检查。

```sh

```
