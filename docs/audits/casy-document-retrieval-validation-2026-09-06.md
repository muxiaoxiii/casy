# 案卷正文与检索验证（2026-09-06）

## 本批实现

- Markdown、TXT、DOCX/DOCM、RTF、ODT 以及旧版 DOC 接入本地 Rust 文档队列。Office 格式使用固定版本 anydoc 0.1.8，文本处理不加载 OCR 模型；Rust 最低版本相应提高为 1.88。
- 完整正文保存为 `document.md`，按不超过 3000 字的段落单元构建检索索引。Markdown 分段保留全部源文本及顺序。文本段落不冒充 Word 物理页码；扫描件继续保留真实页码、坐标与可搜索 PDF。
- 同一套持久任务处理排队、失败、重试、取消后的发布保护、源文件哈希校验和缓存复用。原件不被覆盖。文本输入和提取正文分别限制为 64 MiB；此上限不等于已完成 64 MiB 性能验收。
- 原文检索支持中文分词、三元组全文索引和短词范围内匹配，只查选定文件的最新完成版本。每次最多 200 份文件、500 字查询，命令返回最多 30 处命中，每处最多 6000 字。
- 卷宗检索默认直接返回原文，可选择文件范围、查看页码或段落、展开摘录并请求打开原件。AI 问答另设模式。
- AI 读取节点必须来自选定目录；单次最多 20 个位置、96 KB 正文，累计 192 KB，目录最多 600 节点。回答必须附上已读取来源中的逐字摘录。此校验证明来源和摘录存在，不能证明回答的每项论断均由摘录支持。
- 知识库导入按处理任务版本复用。原件更新后新建独立笔记快照，保留旧版人工批注和子树；笔记移动至其他上级后仍能复用。同版重复导入的子节点数量改为递归计数。旧式未记录版本的导入笔记保留，首次新导入另建明确版本的快照。
- 修复富文本工具栏窄列下逐字竖排的问题。

## 已知限制与后续

- macOS `textutil` 生成的合成旧版 `.doc` 被 anydoc 的 CFB 解析器拒绝，报 MiniFAT 重复引用。已保留失败状态并提示另存 DOCX，未绕过结构校验或声称兼容所有 DOC。相同内容生成的 DOCX 已成功处理。RTF/ODT/DOCM 尚需更多真实样本验收。
- 本批没有调用外部模型。AI 来源约束经过自动测试，但模型端到端答题质量、语义蕴含、延迟及复杂多文档问题还未验收。
- 现有向量索引仍需接入可配置的 embedding 接口/密钥/模型、覆盖全文、正确失效旧向量并报告实际成功数；知识笔记的中文索引与大库加载仍需优化。
- 大笔记编辑、自动保存、历史恢复、双链、文档删除/恢复和长卷宗 OCR 仍属于后续交付门槛。不得据本报告判定整个 Casy 已可交付。
