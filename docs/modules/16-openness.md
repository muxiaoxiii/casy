## 一、职责边界

### 1.1 做什么（目标态）

- **外部访问内部（MCP Server 对外）**：Claude Code / Pi / Codex 等外部工具查询案件/任务/期限/知识。
- **内部访问外部（Skill Runner 对内）**：Casy 调用外部 skill（文书生成/法律检索/格式化/翻译）。
- **智伴层组件化**：没有特权核心，组件 trait + enum 切换。
- **harness 嵌入评估**：文档生成场景复用极简 agent harness 的工具循环。

### 1.2 不做什么

- **不默认立项**：不新增独立 MCP 平台层；不把未实现能力写成现状（architecture.md §3.3）。

## 二、接口设计（目标态）

### 2.1 MCP 对外接口

| MCP 接口 | 操作 | 权限 |
|---|---|---|
| `case.query` | 查案件列表/详情/状态/期限 | 只读，默认开放 |
| `task.query` | 查任务/等待/下一步 | 只读 |
| `knowledge.search` | 查知识库/法条 | 只读 |
| `case.update` | 外部 AI 修改案件/任务 | **需权限确认（Confirmer L3）** |
| `case.create` | 外部 AI 创建任务 | **需权限确认** |

### 2.2 Skill 对内接口

| Skill | 用途 | 加载方式 |
|---|---|---|
| 文书生成 | 答辩状/上诉状/代理词 | 按需（Copilot 窗口触发） |
| 法律检索 | 法条/案例查询 | 按需 |
| 格式化 | 文书格式/编号规范 | 按需 |
| 翻译 | 外文文献/文书 | 按需 |

**判断与执行分离**：智伴层做业务判断（推荐/确认），skill 做具体执行（生成/检索）。

---

## 三、关键机制

1. **权限确认联动**：外部写操作必须走 Confirmer（effective_policy，L3 下限），外部 AI 不能绕过。
2. **隐私分级联动**：外部访问遵守案件级隐私分级——敏感字段不外泄。
3. **skill 安装确认**：防恶意 skill。
4. **harness 沙箱**：仅在文档生成沙箱内运行，不直接访问主数据。
5. **模型可见即记录**：任何到达模型的内容必须能从 `ai_runs` + `ai_context_items` 重建。

---

## 四、分阶段实施

| 阶段 | 范围 |
|---|---|
| **M0-P2** | 智伴层用 trait + enum 实现组件切换（不写死流水线） |
| **P4+** | 第三方插件需求出现时才升级为注册表 + 事件总线 |

> 避免过度工程：先 trait + enum，真需要插件时再上 registry。

---

## 五、验收标准

1. 外部只读查询默认开放，写操作必须过确认。
2. skill 按需加载，不占常驻上下文。
3. 外部访问不泄露高敏案件字段。
4. 智伴组件切换通过配置决定，不硬编码。
