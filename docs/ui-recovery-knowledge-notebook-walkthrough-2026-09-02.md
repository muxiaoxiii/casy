# Casy UI 恢复与知识笔记改造 Walkthrough

日期：2026-09-02

## 本次目标

恢复当前不可用或容易误判为不可用的核心入口：设置、收件箱、任务管理和知识库；同时把知识库从只读表格升级为“笔记列表 + Markdown 编辑器”的日常工作模式。

## 现场确认的问题

1. 设置页本身能够渲染，但全局“今日概览”对话框会覆盖其他路由，造成设置打不开的观感。
2. 收件箱缺少 `clarifyCaseId` 状态，并漏引入 `Clock`、`Warning` 图标，页面初始化和右栏渲染存在运行时错误。
3. 收件箱读取案件时按数组处理，但案件服务实际返回 `{ items, total }`，因此关联案件下拉框为空。
4. 任务页“新建任务”按钮只修改了一个未被任何对话框消费的状态，点击无效果。
5. `TaskRow` 发出的“移至今日、标记等待、稍后处理、厘清”等事件没有在父页面接线。
6. 任务页同样错误地把案件列表响应当成数组，导致任务虽有 `caseId`，但案件名和案件选择可能不可用。
7. 旧知识库在浏览器预览中收到 `{ items, total }` 后直接调用 `.filter()`，触发 `TypeError`，可造成 Vue 更新中断和界面卡死。
8. 旧知识库主要是表格和详情卡片，只能阅读，缺少完整的笔记编辑工作流。

## 已完成改动

### 设置

- “今日概览”只允许在 Today 首页显示。
- 用户切换到其他路由时，早报立即退出，不再阻断设置和业务页面。
- 修复 AI 设置文本框 `rows` 类型告警。
- 补齐飞书设置中传统拉取、推送按钮的真实处理函数和失败提示。

### 收件箱

- 补齐缺失的状态和图标依赖。
- 兼容案件服务的 `{ items, total }` 返回结构，关联案件下拉框恢复。
- 浏览器预览增加可操作的收件箱数据，不再只显示空壳布局。
- 转行动、委派、等待、将来/也许均创建对应任务；创建失败时不再错误归档收件项。
- 处理完成后自动选择下一条待澄清事项。
- 待处理数量改为真实的筛选后数量。

### 任务管理

- “新建任务”打开真实任务抽屉，而不是无效状态。
- 新建和编辑共用同一条持久化链路，并在标题和按钮上区分“新建/编辑”。
- 抽屉内提供明确的“关联案件 (Matter)”选择框；案件服务响应形状已经兼容。
- 接通任务行的编辑、完成、删除、移至今日、标记等待、稍后处理、推迟/提前结束推迟等主要交互。
- 浏览器预览补齐任务新增、更新、删除和稍后处理的可变 Mock，便于在没有 Tauri 后端时做界面回归。

### 知识库

- 新增三栏式知识笔记工作台：
  - 左栏：职能分类、知识图谱和案件沉淀入口；
  - 中栏：笔记搜索、摘要、更新时间和关联案件；
  - 右栏：标题、分类、案件、标签和 Markdown 正文编辑器。
- 支持新建、选择、编辑、自动保存、手动保存和删除笔记。
- 支持编辑、分栏、预览三种模式。
- Markdown 预览先整体进行 HTML 转义，再开放标题、列表、引用、强调、代码和 HTTP(S) 链接等常用语法，避免直接执行笔记中的 HTML。
- 支持笔记关联案件，并在编辑区明确显示关联结果。
- 对列表返回同时兼容数组和 `{ items }`，避免因响应形状差异再次卡死。

## Jot 参考边界

对 `https://gitee.com/MM-Q/jot.git` 做了只读核查。README 宣称 MIT，但仓库根目录 `LICENSE` 是 AGPL-3.0；许可证文件应作为判断依据。因此本次没有复制 Jot 源码、样式或实现，只借鉴了“分类侧栏 + 笔记列表 + Markdown 编辑器”的产品交互模式，并在 Casy 现有 Vue/Tauri/SQLite 服务上独立实现。

若未来希望直接复用 Jot 代码，需要先明确 Casy 是否接受 AGPL-3.0 的开源义务，或向项目作者取得单独许可。

- `npm run typecheck`：通过。
- `npm run test:unit`：2 个测试文件、9 个测试全部通过。
- `npm run build`：通过。构建仍有项目既有的 `html-to-docx` 浏览器外置模块与大分块提示，不是本次引入。
- 浏览器真实交互：
  - 设置页可进入，且没有早报遮挡；
  - 收件箱三栏显示 3 条模拟事项，案件关联可见；
  - 收件项可转为任务并进入下一条；
  - 任务新建抽屉可打开，可选择案件，创建后列表显示任务与案件名；
  - 知识库可新建、编辑 Markdown、关联案件并保存，保存状态正确回落为“已保存”。
- `git diff --check`：本次涉及文件通过。全工作区检查仍会报告 `DocWorkshopView.vue` 中既有的 4 处行尾空格，本次未越权修改。

## 当前边界与后续方向

1. 这次优先恢复了核心可用性。Markdown 编辑器目前是稳定的源码编辑 + 安全预览，还不是 CodeMirror 级别的语法高亮、快捷键、搜索替换和大文档性能方案。
2. 知识库现有版本历史、块级引用和反向链接后端仍保留，但新工作台尚未把这些高级能力全部重新挂回主编辑面。
3. 收件箱 AI 结构化、语音和文件导入仍依赖真实 Tauri 后端和外部配置；浏览器 Mock 只验证 UI 与主动作链路。
4. 最终发布前仍应在 Tauri 桌面壳中，用真实 SQLite 数据各完成一次知识保存、任务关联案件和收件项转任务回归。

建议下一阶段把知识库做成真正的研究工作台：引入可维护的 Markdown 编辑内核、恢复双链/版本历史侧栏，并把 OCR/PageIndex 产出的可检索 PDF 和 Markdown 页面直接沉淀成可引用笔记。
